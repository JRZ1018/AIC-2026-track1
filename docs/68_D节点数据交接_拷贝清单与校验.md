# D 节点数据交接：拷贝清单与校验

## 零、结论先行：**数据必须落到 D 的本地磁盘，SSH 替代不了这一步**

训练器每个 epoch 要对固定训练侧 **82,592 张图片**做解码与增强（`train_peft.py` 从
`DataSetStage1\train\` 按 manifest 读原图）。**这是 I/O 密集的随机读取**，
如果图片放在网络共享/远程挂载上，`workers=4` 的数据加载会成为瓶颈，
每个 epoch 从本机实测的 309 秒退化到不可预测——B 节点每 epoch 721–840 秒已经让
12-epoch 跑了 191 分钟，网络挂载只会更糟。

**所以：**

| 做法 | 能否省掉传输 |
|---|---|
| SSH 远程操作 | ✅ 能省掉"人跑过去"和"手动敲命令" |
| 网络共享 / 远程挂载数据集 | ❌ **不能**，会让训练慢到不可用 |
| SSH 只用于验收与回传 | ✅ 回传量很小（`metrics.json` 数百 KB，`best.pt` 108 MB） |

**但 SSH 确实能省掉一大块**：`artifacts\` 那 25.05 GiB 里，D 真正需要的只有 **0.39 GiB**（见第一节）。
**45.04 GiB → 20.4 GiB，直接砍掉一半以上。**

### 用 SSH 驱动远程训练时的一个真实陷阱（B 已经踩过一次）

**通过 SSH/远程桌面启动训练后，如果会话断开，前台进程会被一起杀掉。** B 那次因机器休眠中断，
12-epoch 跑了 191 分钟才完成，中途必须靠 `--resume` 续跑。

所以远程启动必须**脱离会话**，二选一：

```powershell
# 方式 A：计划任务（最稳，断线、注销都不影响）
schtasks /create /tn "AIC-D-M" /tr "cmd /c cd /d <仓库> && .venv\Scripts\python.exe scripts\train_peft.py --config configs\experiment\p3_stage1_h1init_t2_last4_lr175e6_cwh_mw10_magmix50_16ep_seed1_m.yaml > artifacts\queues\D-M.log 2>&1" /sc once /st 00:00 /f
schtasks /run /tn "AIC-D-M"
```

```powershell
# 方式 B：Start-Process 独立进程（简单，且把输出重定向到日志）
Start-Process -FilePath ".venv\Scripts\python.exe" `
  -ArgumentList "scripts\train_peft.py","--config","configs\experiment\p3_stage1_h1init_t2_last4_lr175e6_cwh_mw10_magmix50_16ep_seed1_m.yaml" `
  -WorkingDirectory "<仓库>" -RedirectStandardOutput "artifacts\queues\D-M.log" -RedirectStandardError "artifacts\queues\D-M.err" -PassThru
```

**不要**直接 `python scripts\train_peft.py ...` 就跑，那样一断线就白跑。
任务单里的 `--resume` 条款是最后一道保险，不该当常规手段用。

#### 方案 A：A 侧起一次性 HTTP 服务，D 用 curl 拉取（**免管理员**）

A 侧（管理员权限的 PowerShell 窗口不需要，普通窗口即可）：

```powershell
cd "D:\aicomp\AICtrack1\artifacts\staging\transfer"
& "D:\aicomp\AICtrack1\.venv\Scripts\python.exe" -m http.server 8000 --bind 0.0.0.0
```

D 侧（`curl` 支持断点续传，中断后重跑同一条命令即可接上）：

```powershell
mkdir D:\aic-transfer -Force
cd D:\aic-transfer
curl.exe -L -C - -O http://10.40.51.217:8000/DataSetStage1.tar
curl.exe -L -C - -O http://10.40.51.217:8000/artifacts-minimal.tar
```

**为什么要打成 tar**：数据集有 **128,185 个文件**，逐个下载要发 12.8 万次 HTTP 请求，
元数据开销会让 20 GiB 变成几小时；打成 **2 个 tar** 后只有 2 个大文件，
连续顺序读能跑满链路带宽。图片本身已是压缩格式，**不要再加 `-z`**（白耗 CPU 且几乎不缩体积）：

```powershell
tar -cf DataSetStage1.tar -C "D:\aicomp\AICtrack1" DataSetStage1
tar -cf artifacts-minimal.tar -C "D:\aicomp\AICtrack1\artifacts\staging" artifacts-minimal
```

> `tar` 是 Windows 10 1803+ 内置的 bsdtar，本机已确认存在（3.7.2）。
> **注意 tar 的 8 GiB 条目上限问题**：单个文件都不超过 400 MB，包体本身是多个文件，
> 现代 bsdtar 无此限制，但保险起见仍按上表拆成两个包。
> **不建议加 `-z`**：JPG 已压缩，`-z` 只会把 CPU 跑满而体积几乎不变。

D 侧解包：

```powershell
tar -xf DataSetStage1.tar -C "D:\aicomp\AICtrack1"
tar -xf artifacts-minimal.tar -C "D:\aicomp\AICtrack1\artifacts"
```

#### 方案 B：croc（免管理员、跨网可穿透）

如果 `ping` 不通（校园网客户端隔离），用 `croc`：它免安装、端到端加密、
自动 NAT 穿透，两端各跑一条命令即可，**不需要任何管理员权限**。

A 侧：`croc send D:\aicomp\AICtrack1\artifacts\staging\transfer\DataSetStage1.tar`
D 侧：按 A 给出的口令 `croc <code>` 接收。

#### 方案 C：SMB 共享（**需要管理员，本机当前不可用**）

只有在 D 与 A 同网段且不隔离、且**你愿意用管理员权限**时才考虑：

```powershell
# 需要管理员
New-SmbShare -Name "AIC" -Path "D:\aicomp\AICtrack1\artifacts\staging\transfer" -ReadAccess "Everyone"
Set-NetFirewallRule -DisplayGroup "File and Printer Sharing" -Enabled True -Profile Any
```

然后把网络类别从"公用"改为"专用"（否则默认阻止共享）：

```powershell
Set-NetConnectionProfile -InterfaceAlias "WLAN" -NetworkCategory Private
```

**我不建议走 SMB**，原因有三：需要管理员权限（当前 shell 没有）；
要把 WLAN 从"公用"降级为"专用"（在校园网上降低本机防护）；
校园网隔离下大概率直接不通。**方案 A 更简单也更安全。**

### 带宽预期（WLAN 实测经验）

| 链路 | 典型吞吐 | 20.4 GiB 耗时 |
|---|---:|---:|
| WLAN 802.11ac 良好信号 | 30–70 MB/s | 5–12 分钟 |
| WLAN 拥塞 / 802.11n | 8–20 MB/s | 20–45 分钟 |
| 千兆有线 | ~110 MB/s | 3–5 分钟 |

**tar 打包后是纯粹的顺序读，能跑满链路**；这也是必须打包的第二个理由
（散文件走 HTTP 会被请求往返拖垮）。

## 二、拷贝命令

目标盘符按实际替换（示例用 `E:`）。**必须用 `/MT` 多线程**，否则 14.5 万个小文件会极慢：

```powershell
$dst = "E:\AIC-D-transfer"

robocopy "D:\aicomp\AICtrack1\DataSetStage1" "$dst\DataSetStage1" /E /COPY:DAT /R:2 /W:2 /MT:16 /NFL /NDL /NP

robocopy "D:\aicomp\AICtrack1\artifacts" "$dst\artifacts" /E /COPY:DAT /R:2 /W:2 /MT:16 /NFL /NDL /NP
```

**注意：**

- **不要用 `/MIR`（镜像）**——它会删除目标端的多余文件，插错盘会误删。
- `/COPY:DAT` 保留数据、属性、时间戳；`/R:2 /W:2` 限制重试，避免卡在坏文件上。
- 文件系统用 **exFAT**（通用）或 **NTFS**（两边都是 Windows 时更稳）。**不要用 FAT32。**
- 建议再追加一次 `/L` 干跑先看清单：把上面命令末尾加 `/L` 即可，不实际复制。

## 三、校验：**不要**对 45 GiB 做全量 SHA-256

全量哈希两边各要读 45 GiB（各约 15–30 分钟），**性价比低**。理由：

- robocopy 拷贝时自身已逐文件校验，绝大多数损坏会被它抓到；
- 真正"载荷关键"的小文件只有 **340 MB**，可以完整哈希；
- 而**训练图片的正确性由任务单第 1 步的关卡直接证明**——epoch 1 的 Top-1 精确等于
  `0.695432961`，只有在图片内容、划分、初始化头、CLIP 权重全部逐字节一致时才可能出现。

**所以：小文件全量哈希 + 关卡验证，两步合起来覆盖了全部风险，而不是把 45 GiB 哈希两遍。**

### 3.1 载荷关键文件清单（6 个，共 340 MB）

**拷贝完成后，在 D 的机器上对下列文件取 SHA-256，必须逐一精确相等：**

| 文件（相对 `AIC-D-transfer\`） | 字节 | SHA-256 |
|---|---:|---|
| `artifacts\audits\stage1\train\samples.csv` | 24,149,089 | `212f645a0d027cc4f2aa1a6d2f81f0175e8a3441b6fa6d001947038e00ba75ef` |
| `artifacts\audits\stage1\train\split.csv` | 7,431,624 | `9eb97e2b89da76f64323c2800d6c524a8455e31eaa9b0dab1917b7e4b877fb31` |
| `artifacts\audits\stage1\train\label_conflicts.csv` | 79,615 | `d06a03bf23b54e663bfc849236f855dfeb61251262329210a72274b2c4df70f1` |
| `artifacts\audits\stage1\metadata\classes.csv` | 4,940 | `ff8754d203c97e59adbc5103df83e28ac954ccda7482e31fba696db507fe1ee6` |
| `artifacts\weights\ViT-B-32.pt` | 353,976,522 | `40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af` |
| `artifacts\experiments\20260911-p3-h1-linear-adam-e100-seed42\best.pt` | 1,029,069 | `e85d53d446fef914c7cec74faa1ede792b7774bb71ec057dee2b551d6cf485af` |

一行命令：

```powershell
$root = "E:\AIC-D-transfer"
@(
 "artifacts\audits\stage1\train\samples.csv",
 "artifacts\audits\stage1\train\split.csv",
 "artifacts\audits\stage1\train\label_conflicts.csv",
 "artifacts\audits\stage1\metadata\classes.csv",
 "artifacts\weights\ViT-B-32.pt",
 "artifacts\experiments\20260911-p3-h1-linear-adam-e100-seed42\best.pt"
) | ForEach-Object {
  $p = Join-Path $root $_
  "{0}  {1}  {2}" -f (Get-FileHash $p -Algorithm SHA256).Hash.ToLower(), (Get-Item $p).Length, $_
}
```

**其中 `samples.csv` 与 `split.csv` 最关键**：任何一个字节不符，epoch 1 的 Top-1 就不会等于
`0.695432961`。

## 四、`artifacts\` 里 47 个"头初始化器"的混淆风险（重要）

`artifacts\experiments\` 下有 **47 个名字里带 `h1init` 的目录**，其中**两个是真正的候选头初始化器，
且两个文件都恰好约 0.98 MB，肉眼无法区分**：

| 路径 | 用途 | 能否用于固定验证 |
|---|---|---|
| `20260911-p3-h1-linear-adam-e100-seed42\best.pt` | **唯一可用于固定验证与筛选的头**（只在固定 train 侧训练，未见过验证集） | ✅ **用这个** |
| `20260912-b-final-h1-linear-full-e100-seed1\final.pt` | 全量头（已在全部 103,218 张上训练，**见过固定验证集**） | ❌ **会泄漏，禁止用于固定验证** |

`docs/44` 记录过这个泄漏纠正，两代数字**不可跨代比较**（差距达 0.142）。
本项目的筛选/关卡配置一律用 `seed42\best.pt`；全量复训配置才用 `final.pt`。

**给 D 的提醒**：不要自己挑头文件，一律按配置文件里写死的路径来。

## 五、D 侧的落地步骤

1. `git clone` 仓库（或按 `docs/17` §2 的方式取得仓库）
2. 把 `AIC-D-transfer\DataSetStage1\` 放到 `<仓库>\DataSetStage1\`
