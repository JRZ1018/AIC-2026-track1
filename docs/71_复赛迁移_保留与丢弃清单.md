### 1.3 与初赛的差异（决定迁移动作）

1. 类别数 500 → **750**：分类头输出维度、四位编号语义、类频统计全部改变。
2. 训练量 ×1.44：单次 12-epoch 全量的成本按此比例变化（见 §6）。
3. **新增长尾分布**：复赛与半决赛都偏，而测试集均衡 → 训练集的长尾会系统性压低 Top-1。
4. 权重最高（60%）的半决赛数据量**比初赛还小**，长尾最极端。

## 2. 硬约束速查（跨阶段不变）

来源：`AGENTS.md` §2 + 官方赛题规则"十一、赛题约束条件"。

- 骨干只能用 **CLIP ViT-B/32**，不得替换为其他或更大视觉基础模型。
- 只允许 **OpenAI 官方公开预训练权重**（`openai/clip` / HuggingFace 对应版本）；不得用 LAION、OpenCLIP 等来源权重。
- **禁止多模型集成、模型融合、多模型投票**；最终必须是单一模型 + 单一推理流程。
- **每阶段只能用该阶段官方数据**：复赛不得用初赛数据，半决赛不得用初赛和复赛数据。
- **不得引入任何额外数据集**（公开、私有、人工补充标注均不可）。
- **测试集只能推理**：不得以监督/自监督/无监督/伪标签等方式参与训练、筛样、调参或后处理。
- 训练全过程（含噪声筛选）必须能由最终提交代码复现；**人工清洗不得成为必要前置**。
- 提交物：`pred_results.csv`（四位类别编号）+ 打包 ZIP；另需可复现代码、环境说明、模型文件或容器。

## 6. 算力账（按实测吞吐估算，供排产）

实测基准（B 机 RTX 4060 Laptop 8 GB，`docs/67`/`69` 对应的 12-epoch 全量）：

| 指标 | 实测值 |
|---|---|
| 训练吞吐 | 93.5–99.2 samples/s（`train_samples_per_second`） |
| 单 epoch | 训练 ≈840 s + 验证 ≈200 s ≈ **17 min** |
| 12 epoch 全量 | ≈**191–198 min（3.2–3.3 h）** @ 103,218 样本 |
| 峰值显存 | 1,146 MiB（8 GB 卡的 14%） |

按线性外推（当前瓶颈是 CPU 图像解码与磁盘 I/O，不是算力）：

| 阶段 | 训练样本 | 相对初赛 | 单次 12-epoch 预计 |
|---|---:|---:|---:|
| 复赛 | 148,695 | ×1.44 | ≈ 4.6–4.8 h |
| 半决赛 | 90,197 | ×0.87 | ≈ 2.8–2.9 h |

推论（供 A 判断，非结论）：
- 9/21–10/11 共 3 周窗口，若维持双机串行，可容纳的**全量 12-epoch 次数约为 60–80 次**（复赛口径）。
- 租用大显存多核机器时，本方案单跑仅占 1.1 GB 显存，**并发 4–8 路**比单跑提速更划算；选型时 CPU 核数、内存与本地 NVMe 比 GPU 算力更关键（数据管线才是瓶颈）。

2. **数据只读审计**：对复赛 `DataSetStage2/` 做只读扫描 → 文件数、类别数（应为 750）、每类样本数、坏图统计、哈希摘要。
3. **重建索引与划分**：manifest → split（固定种子）→ label_conflicts；保留生成命令。
4. **重建"复赛版 H1"**：随机初始化线性头 + 复赛冻结特征训练，**不复用初赛头权重**。
5. **重算守卫值**：`expected_initial_top1` 及容差按复赛固定验证集重新测定。
6. **重跑基线阶梯**（`AGENTS.md` §4.2）：加载冒烟 → 冻结特征线性探测 → 单模型微调基线 → 本地模拟提交校验（不提交）。
7. **方法扫描**：以 §4 的假设为起点做粗筛（建议三轴：视觉 lr × 解冻块数 × 去偏/加权强度），各候选再 3 种子确认。
8. **长尾专项**：报告 head/mid/tail accuracy、macro accuracy、最差类召回、每类保留率（协议见 `docs/41`/`42`）。
9. **记录与回传**：每个运行目录齐全（`config.yaml/command.txt/environment.txt/git_state.txt/metrics.json/summary.md/artifacts_manifest.json`）；checkpoint 与日志只走私有大包，不进公开 Git。

## 8. 跨机等价性（若新增租用机，必须先做）

现有门禁依赖"不同机器逐位一致"（见 `docs/66`：item L 复现验收，48 个权重张量与 RNG 状态逐位相同）。新增 H20 等异构机器后：

1. 先做**等价性验证**：同 config + 同 seed，在两台机器各跑 1–2 epoch，比对 epoch-1 Top-1 与权重是否逐位一致。
2. 若不一致，二选一并写入任务单：
   - 所有复赛实验统一迁到新机器（保持内部可比）；
   - 或明确"原机器为唯一裁判机、新机器只做粗筛"，禁止两侧结果混入同一门禁。
3. 关注 `torch.backends.cudnn.allow_tf32`（默认 True）在不同架构上的卷积路径差异；记录精度开关到 `environment.txt`。
