- 总体 Top-1 **84.2335%**，macro **84.2211%**，500 类全部有评估支持，零召回类 0。
- head−tail 准确率差 **+2.85 点**（head 高于 tail）。
- 观察：**mid 分层是当前最弱分层**（82.26%，比 tail 低 2.0 点）。这与“类数越多越差”的朴素预期不同，说明在初赛近均衡数据上，瓶颈更可能来自类别间细粒度混淆，而不是单纯的样本数少；`top_confusions` 也显示若干近似对称的混淆对（如 217↔421、155↔195、266↔424、358↔413、343↔481）。
- 该 checkpoint 在完整官方训练集（103,218 张）上为 99.3032%（见第 4.3 节），说明它的泛化差距很大，固定验证的 84.23% 属于“近邻分布”，仍不是干净泛化成绩；线上 58.4011 才是无泄漏证据。

### 结论

1. **长尾确实饿死尾类**：四者共用同一特征口径时，H1 参照（每类 161–170 张）tail 为 82.90%，而 L1 的 head 分层（每类 168–170 张）仍有 80.59%、tail 分层（每类 8 张）暴跌到 21.35%，出现 **31 个零召回类**，tail 最差类召回为 0。这是本轮最直接的失效模式证据。
2. **类频偏斜本身有额外伤害**：L2 与 L1 的 tail 类每类都只有 8 张训练样本，但 L2 类别均衡、L1 长尾偏斜；tail 准确率分别为 45.11% 与 21.35%，零召回类 4 对 31。因此在同等样本稀缺度下，类频偏斜使尾类表现再降约 23.8 点。
3. **样本稀缺是主因**：L2（8 张/类）45.31% → L3（20 张/类）55.71% → H1（166 张/类）82.92%，每类有效样本数是当前最强解释变量。复赛机制设计应优先保证**每类最低保留**，而不是只做全局类均衡采样。
4. **触发预注册停止线**：最稀缺桶（≤8 张）L1 类均召回 21.29% < 0.30，零召回类 31 > 25，按 `docs/41` 第 6 节判定“当前流程会在长尾下饿死尾类”，不得把未加最低保留的机制直接送入复赛，必须先补“每类最低保留 + 类感知阈值”。
5. 长尾评估划分（9,823 张，head 分层只有 1 张、按预注册规则标记为不可用）上四者 Top-1 与 mid/tail 准确率分别为：H1 81.36%（mid 80.87% / tail 81.67%）、L3 58.80%（mid 57.70% / tail 59.49%）、L2 45.08%（mid 44.68% / tail 45.33%）、L1 33.62%（mid 54.92% / **tail 20.47%**）。该划分的排序与固定验证一致，且再次显示 L1 的 mid 与 tail 出现明显分层落差。

### 口径说明（重要）

- 本节所有头都在**同一 frozen 特征缓存**上训练与评估，因此四者之间的相对比较有效；缓存已用 64 张验证图片重新提取核对，`cosine(新提取, 缓存)` 均值 0.99893、最小 0.99419，缓存内容可信。
- 但缓存口径与最终 raw-image 训练/推理口径不同：同一 H1 全量头在缓存上是 82.92%，在 raw-image 流水线上为 82.91%（见下表核验），而旧的 `20260911-p3-h1-linear-adam-e100-seed42/best.pt` 只有 68.70%，是本报告早期版本误用的弱参照。用于 T2 候选初始化与提交的是 `20260912-b-final-h1-linear-full-e100-seed1/final.pt`（raw-image 82.91%），本节已改用该 checkpoint 作为 H1 参照。
