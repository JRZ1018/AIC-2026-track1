## 1. 本批结论

Stage 2 不再只依赖路径文本的静态隔离。正式启用的 Stage 2 数据配置必须先冻结经审计的
训练样本数、测试样本数和类别数；训练、恢复、评估与推理所用 checkpoint 必须同时匹配：

- `competition_stage`；
- class mapping SHA-256；
- train manifest SHA-256；
- split SHA-256；
- OpenAI 官方 CLIP 权重 SHA-256；
- `num_classes`。

任一字段缺失或不一致都会在加载模型状态、开始训练或开始推理前硬失败。历史 Stage 1 配置
没有新增字段，仍按旧契约兼容读取；新 Stage 2 配置不得利用该兼容路径。

## 2. 数据与执行契约

`DatasetConfig` 新增以下运行时字段：

```yaml
competition_stage: stage2
contract_confirmed: false
expected_train_count: null
expected_test_count: null
expected_num_classes: null
```

Stage 2 模板继续保持不可执行。数据到手后必须先完成只读审计，再将三个 `null` 替换为实测值，
确认类别映射和目录契约，最后才可把 `contract_confirmed` 与实验的 `execution_enabled` 打开。

运行时验证规则如下：

1. 实验与数据配置必须声明相同的比赛阶段；
2. 可执行的阶段配置必须 `contract_confirmed: true`；
3. train、test、class 三个期望数量全部必填且为正整数；
4. 入口拿到实际数量后必须逐项精确相等；
5. `execution_enabled: false` 的设计模板允许保留未知占位，但不能训练或推理。

当前模板中的数量仍为空，避免把公告规模当作已经验签的数据事实。

## 3. Checkpoint provenance

新增 `src/aictrack1/engine/provenance.py`，以一个统一的 `CheckpointProvenance` 对象生成并验证
六项身份。该身份已接入：

- 冻结特征头训练、恢复和最终头 checkpoint；
- PEFT 训练、恢复、头初始化、最佳/最终 checkpoint；
- 长尾头评估与诊断模型加载；
- 冻结头与最终 PEFT 两条推理/提交构建路径。

Stage 2 的 PEFT 头初始化也必须来自同阶段、同 mapping、同 manifest、同 split、同官方权重和
同类别数的冻结头；不能加载初赛 H1 头或仅凭张量形状相同绕过门禁。

B03 解决的是“身份错配时硬失败”，不替代真实数据审计。复赛数据到手后仍须：

1. 验签原始文件并实测 train/test/class 数量；
2. 确认官方类别映射、test 层级和提交首列契约；
3. 冻结 train manifest 与 split，并写入正式 Stage 2 配置；

5. 通过一批轻量冒烟后，才申请正式训练资源。

任何实际数量与当前公告规模不同都应先停机核对，不为迎合预期而修改数据或放宽门禁。
