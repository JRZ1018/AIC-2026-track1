## 1. 当前运行模型

后续只使用当前机器。A 是唯一训练调度者、代码/配置维护者和线上提交执行人；B 是独立复核人，
负责核对数据/配置/产物哈希、训练事实和提交包，不在同一机器上另起训练。A 暂时不可用时，B
只能保留现场、停止新任务并按已签字任务单恢复；未完成书面交接前不得自行选模或提交。

唯一事实源：代码与模板在 Git；实验事实在 `experiments/index.csv`；提交事实在
`submissions/ledger.csv`；大产物以任务目录内 `artifacts_manifest.json` 及 SHA-256 为准。聊天和
终端滚屏不是事实源。

## 2. 阶段责任与双人复核

| 环节 | 唯一执行人 | 独立复核人 | 必须停机的分歧 |
|---|---|---|---|
| 官方包下载与原始哈希 | A | B | 来源、大小或哈希不一致 |
| 只读审计、映射、split | A | B | 数量、类别或官方映射不能解释 |
| 配置冻结与训练调度 | A | B | commit/config/input 哈希不一致 |
| 训练/恢复 | A | B 复核日志与产物 | 训练锁、NaN/OOM、来源错阶段 |
| 锁模与 test 推理 | A | B 复核唯一 checkpoint | checkpoint/命令/台账任一不一致 |
| 出包与线上提交 | A | B 复核 CSV/ZIP 哈希 | 包校验失败、次数不明、窗口不明 |
| 报告与复现材料 | A | B 逐项验签 | 数字无来源、方法无法对应配置 |

提交严格执行“四眼原则”：A 生成并上传，B 只核对文件名、行数、checkpoint 哈希、CSV/ZIP
哈希和台账空闲名额。B 不点击提交，避免重复消耗每日名额。

## 3. 任务单与交接门禁

正式任务统一复制 `docs/templates/stage2_task_order.md`。开始前必须完成：

1. 40 位 commit、唯一配置及 SHA-256、阶段、数据/划分/映射/权重哈希；
2. 唯一命令、唯一输出目录、资源预算、成功/停止条件和续跑命令；
3. `scripts/manage_training_lock.py status` 显示无活动训练，输出目录不存在或为经确认的恢复目录；
4. A 与 B 对任务单输入逐项核对；任务中途变更必须新建任务 ID 和 commit。

交接时记录当前 PID、epoch/step、最近 checkpoint、训练锁 token、日志尾部、剩余磁盘和 GPU 状态。
半成品目录不得覆盖、删除或被队列自动跳过；由 A 明确选择恢复、封存或使用新任务 ID 重跑。

## 4. 数据开放首日值守顺序

| 时间段 | A | B | 放行条件 |
|---|---|---|---|
| 0:00–0:30 | 记录官方来源并下载/验签 | 核对公告、窗口和原包哈希 | 来源和原包身份一致 |
| 0:30–1:30 | 只读结构审计 | 独立核对数量、类别、坏图、路径 | 无无法解释的异常 |
| 1:30–2:00 | 建立官方映射与提交契约 | 复核样例、首列和标签集合 | 契约测试全过 |
| 2:00–3:00 | 冻结 split、运行 B09 判定 | 复核 L0/L1/L2 证据 | 报告可重复生成 |

若任一段超时，顺延后续工作；不以跳过验收换取更早开训。

## 5. 异常升级表

| 异常 | 立即动作 | 保留证据 | 重新放行 |
|---|---|---|---|
| 官方包损坏/大小不符 | 停止解压，不覆盖原包 | URL、字节数、SHA-256、下载日志 | 重新下载并双人验签 |
| 数量/类别/目录异常 | 停止映射与训练 | 审计 JSON、样例相对路径 | 官方说明或可审计契约解释 |
| CUDA OOM/温度异常/NaN | 停止 trainer，保留锁和目录 | 命令、日志、`nvidia-smi`、checkpoint | A 发布新任务单或确认安全恢复 |
| pytest/文件 ACL 失败 | 不降级跳过测试 | 完整错误、精确目录 ACL | 使用已知可写临时目录后测试通过 |
| 训练崩溃/断电 | 不自动清锁、不删除半成品 | last checkpoint、日志、锁 token | 进程已退出且恢复门禁通过 |
| CSV/ZIP 校验失败 | 不上传，保留上一个已验签包 | validator 输出、CSV/ZIP 哈希 | 修复后重新生成并双人验签 |
| 平台不可用/提交状态不明 | 不重复点击 | 时间、页面截图、包哈希 | 状态明确且名额确认后操作 |
| 账号/资格/窗口不明 | 不下载、不提交 | 官方页面或通知快照 | 队长/官方书面确认 |

任何异常都不得通过删除锁、改标签、手工修 CSV、临时升级依赖或换 checkpoint 绕过。涉及官方解释的
问题追加到 `docs/compliance_questions.md`；未答复前采用更严格口径。

## 6. 每日收尾

- A：确认 trainer/队列状态、D: 余量、最新 checkpoint、Git commit、实验/提交台账和次日任务单。
- B：复核新产物哈希、异常是否闭环、每日提交次数和回退包仍可用。
- 双方：确认没有数据、checkpoint、预测、凭据或 Cookie 进入 Git；唯一下一任务明确。
