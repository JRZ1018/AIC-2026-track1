# B 通宵队列启动故障分析与恢复

日期：2026-09-15。

## 现场结论

旧训练 commit `42203b84a0bc00594113e75c2d4ff32ae1b0b850` 的首项在初始化 DataLoader 时只向 stderr 输出了一条 PIL `UserWarning`，随后 Python 主进程消失，四个 worker 成为孤儿，`Tee-Object` 因继承的管道句柄未关闭而持续等待。实验输出目录为空，没有 `last.pt`、metrics、模型前向或 test 访问证据。

高概率根因是队列脚本的 `& $Python @arguments 2>&1 | Tee-Object`：Windows PowerShell 会把 native stderr 包装为错误记录；与 `$ErrorActionPreference = "Stop"` 组合后，普通警告可能终止调用管道。worker 可执行映像显示基础 Python 路径并不能单独证明虚拟环境错配，因为 Windows venv 解释器本身基于该基础安装。

因此禁止在旧 commit 上原样重跑。该失败不计作模型、配置或数据失败，也没有可恢复 checkpoint。

## 修复范围

只修改 `scripts/run_b_overnight_queue.ps1` 的进程承载方式：

- 每项训练使用 `Start-Process` 启动独立隐藏 Python 主进程；
- stdout 与 stderr 分别重定向到带时间戳的日志文件，不再进入 PowerShell 对象管道；
- 使用进程对象的 `WaitForExit()` 等待主进程并读取明确退出码；
- 保留原有配置顺序、参数、输出目录、完成项跳过和 `last.pt` 恢复逻辑。

15 份训练配置、120 epochs、数据、初始化器、seed、学习率、batch 和门禁均不变。重新启动前允许保留旧的空输出目录和旧队列日志；新脚本会把空目录视为可首次启动，不覆盖任何有效训练产物。
