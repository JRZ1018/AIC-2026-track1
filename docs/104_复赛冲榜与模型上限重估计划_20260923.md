## 3. 核心研判：有架构上限风险，但还不能断言要换骨干

当前模型的实际路径是：OpenAI 原始 ViT-B/32 → Stage2 冻结 CLIP 特征上的 750 类**线性 H1** → 固定 H1 → 只微调末六视觉块、AC 加权 → 单张 224×224 图像、单个全局图像向量、线性分类。代码证据：`src/aictrack1/models/heads.py`、`peft.py`，`configs/experiment/stage2_c2_peft_ac_last6_full_14ep_seed20260921.yaml`。

三个**待证伪假设**按信息增益排序：

1. **分类头失配/长尾先验主导。** H1 在原始冻结表征上训出，PEFT 随后改变特征几何但头始终冻结。Stage1 冻结头有效，不等于 Stage2 的新分布与更深 PEFT 仍适用。先在**同一 C2 checkpoint 的冻结视觉特征**上，仅用固定 train 分区重训头并在固定 validation 比较，几乎不用再次训练视觉网络。这也是[长尾表征—分类器解耦](https://github.com/facebookresearch/classifier-balancing)的合规、低成本最小机制。
2. **全局表征丢失细粒度线索。** ViT-B/32 的 224 输入只有 7×7 个空间 patch；当前只读最终全局图像向量并用线性头。官方[CLIP 模型卡](https://huggingface.co/openai/clip-vit-base-patch32)也提醒其细粒度识别有限。[TransFG](https://arxiv.org/abs/2103.07976)提出利用局部 patch 的细粒度判别思想，但**不能**直接换其骨干/权重。先比较单模型、同一 OpenAI ViT-B/32 的原生 224 预处理、局部 token 池化/中层特征与现有全局向量；再决定是否改造读出头。图像输入升到 288/336 需插值位置编码，是否仍满足“严格 ViT-B/32”先向组委会确认，未获确认不进入正式链路。
3. **噪声/长尾与表征漂移耦合。** AC 在 Stage2 优于 CE，但尾类与错标类可能同时被压权；简单保护、采样和先验已失败。需要用训练分区内部的损失轨迹、支持数、精确冲突与近重复结构，分开测“错标识别能力”和“尾类有效质量”。若重做噪声机制，应先做离线判别诊断，再少量受控试验；不能把低损失当成泛化证据。

“推翻重建”是**模型头/视觉读出、训练目标、适配与数据评价链路**的重构，不是换用 ViT-B/16、DINOv2、Swin、其他权重、外部物种名、额外图像或多模型推理。750 类官方映射只有数字 ID，`class_name` 为空；依赖语义类名的文本 Prompt/零样本分支目前没有合规输入，不准用联网搜索或人工/LLM 补类名来规避。

## 5. 新实验体系：先测上限，再买训练时间

> Day 0 实测更新（2026-09-23）：`docs/105_复赛Day0验证代理与双折审计_20260923.md` 发现旧 fixed split 的 largest-first 分组法使验证集中 50.37% 样本来自非单例近重复组、9.60% 为跨标签精确冲突，分别远高于 train 全体 10.94% / 2.61%。已冻结 seeded-random 第二折（均为 20% 验证、750 类全覆盖、组泄漏 0），其对应比例为 10.48% / 2.59%。因此旧折仅作历史配对基线，新折必须重新训练 H1/PEFT 后才可评估；两折不得直接平均或把旧折绝对分数当作线上无偏预测。

### 5.1 评估与代码核验门禁（不先训练）

1. `docs/100` 的 tail 文书错误已从原始 metrics 更正；执行时仍须核对 `experiments/index.csv`，从原始 metrics 重算所有 R2–C2 曲线，分清“同 seed 同 epoch”“best epoch”“全量线上”三种不可互换的比较。
2. 只用 Stage2 **train** 建立独立于现有 20% 固定 split 的第二个重复簇隔离折，预注册种子与分组算法；验证来源、类别数、各类支持、跨标签冲突分布和群组泄漏。**第二折 PEFT 对照必须从官方权重和该折训练分区重训 H1/视觉，不能拿已见过其验证样本的旧 C2 权重直接评估。** 不要删验证样本再把分数称作官方代理。
3. 对固定验证报告 overall、macro、tail、head/mid、零召回、每类预测偏置、精确冲突/非冲突；按重复簇与类分层估不确定性。尾类最少仅 1 张 validation，单类召回不能用于细粒度调参。
4. 从归档的 C2 checkpoint 复现固定验证 logits，核对预处理、750 类映射、头加载/冻结、checkpoint 标识和 CSV 文件名契约。**不读取 test 图片或预测**作误差分析；线上 57.18 只能说明代理预测失败，不能用于推断 test 类别/阈值。

### 5.2 架构上限诊断（本轮最优先的 GPU 工作）

在固定 split 的 Stage2 train/validation，分别提取**官方原始 CLIP**与**C2 固定 split 8-epoch `best.pt`** 的单视角特征，所有头只用 train 分区拟合，验证只用于评估；**绝对不能用见过全部 train 的 C2 全量 14-epoch `final.pt` 生成用于选模的验证特征**。缓存按模型、预处理、manifest、split、代码与权重 SHA 命名。先做：

| 实验 | 固定视觉特征上的单一分类器 | 要回答的问题 |
|---|---|---|
| D0 | 复现原 H1/冻结头，核对现有 C2 分数 | 测量链是否正确？ |
| D1 | C2 表征 + 自然采样重新训练线性头 | 视觉改变后头是否失配？ |
| D2 | 同一 C2 表征 + 轻度 class-balanced cRT / tau-normalization，最多各一个固定点 | 均衡测试先验能否通过**后训练头**改善，而无需重训骨干？ |
| D3 | 同一特征 + 小型残差/余弦头，复杂度受限且从 Stage2 train 随机初始化 | 线性读出能力是否限制分数？ |
| D4 | 原始 CLIP 与 C2 特征的类内/类间分离、近邻一致性及线性头差值 | 若换头无效，视觉表征是否才是主瓶颈？ |

头部改造是**同一个最终模型里的一个头**，不是外接第二个视觉骨干或投票。D0–D4 先跑一个预注册主折；最佳机制再用**在第二折重新训练的 PEFT 视觉特征**及 2–3 个头初始化种子确认。若 C2 特征上的重训头使两个折的 balanced-proxy/macro 稳定 **+1.0 pp 或以上**、overall 不出现明显退化、零召回不增加，则优先完成“视觉 PEFT → 单头后训练”的新架构，暂缓更贵的端到端试验。低于 +0.3 pp 且置信区间跨 0 的头部改动止损；0.3–1.0 pp 结合成本与尾类稳定性决定。

### 5.3 只有 D0–D4 指向视觉瓶颈才启动的架构重构

- **V1：头与末六块共同适配。** 从同一 Stage2 H1 + 官方 CLIP 出发，对照现有冻结头 last-6；小学习率头参数组、AC 其他不变。追踪头权重漂移、训练/验证间隙和尾类。若 joint head 易过拟合，比较 PEFT 后的 cRT，而不是立刻增加 epoch。
- **V2：输入/局部细节。** 首先固定 224 与同一骨干，只改训练 crop（减少主体被截断）或视觉 token 读出，分别做最小消融；检验图像宽高比、裁剪敏感性与易混淆类的 train-only 诊断。patch token/中层读出若需要添加模块，必须明确最终仍是单一 CLIP ViT-B/32 + 单头。高于 224、位置编码插值、测试时多裁剪均列为**规则待确认**，不能先拿来正式冲榜。
- **V3：视觉适配正则/参数化。** 若 V1/V2 提升但后期回落，测试对官方原始参数的 L2-SP/特征约束；若 last-6 容量见顶，比较视觉 LN/投影或 VPT/Adapter 的一个最小版本。不能把已有初赛 LoRA 失败外推为所有新 PEFT 都无效，也不能启动全排列网格。
- **N1：噪声与长尾联治。** 仅在 D0–V3 的剩余错误证明确属高损失错标/少样本问题时，先用训练内精确冲突作**部分可观察**的噪声代理，测 AC/新信号 AUC、每类有效样本量和尾类负效应；再测试一个类感知可靠性目标或自动软标签。精确冲突不是真实噪声全集，不能在它上面过拟合。

每个 V/N 候选只改一个主机制，**同一 seed、同一折、同一训练步数**配对；当且仅当单机制有证据才做有明确问题的联合消融。不再以“把显存占满”或“凑够十个实验”为目标。

### 5.4 晋级、出包和止损

- 先以固定验证 **Top-1 + 类均衡 macro 的双代理**看方向，额外守住 tail、零召回和 AC 有效质量；使用配对样本/重复簇差值与第二折，而非孤立的 0.2 pp 阈值。排名 15% 所需差距巨大，优先投入有 **≥1 pp 稳定本地收益**或揭示大结构问题的实验；较小稳定收益可作为后续组合模块，但不抢主线资源。
- 两个互相独立的候选同时需要 L20 时，**先采用现有串行锁**。此前 2-epoch 双任务并发总墙钟约 550 秒、两次串行参考约 2×297 秒，节约约 7% 墙钟，尚不足以证明并发值得承担竞争与故障风险（`docs/99`、`docs/94`）。原报告“总吞吐仅为单任务 0.54 倍”的算式/口径值得复核：若两个任务都在 550 秒完成，按完成任务数算应约为 `2×297/550≈1.08` 倍。只有先核对基准口径、找出 DataLoader/CPU 竞争并重新通过受控吞吐门禁，才恢复双任务并行。L20 当前 workers16/prefetch4/batch64 为速度—分数已验收锚点。
- 全量模型必须按预冻结配方从 OpenAI 原始权重和 Stage2 **全部 train** 重训相应视觉与**唯一头**；固定验证 H1 不得混成全量头。最终在锁模后只对 test 推理一次，生成唯一 `pred_results.csv`；每天最多两次只提交机制不同、证据充分的新包，不提交重复 ZIP 或故意耗额度。
- 若两个主要架构家族在双折验证均没有 ≥1 pp 提升，或本地上升而后续线上仍长期与验证不一致，暂停昂贵超参搜索，重新审计训练—验证协议、预处理、原始标签语义和提交映射，并咨询官方；**不能**读取 test 标签、预测分布、伪标签或用榜分逐点调参。
