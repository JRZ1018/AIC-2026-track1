## 1. 决策依据与规则边界

- 当前已记录的最高线上分为 **61.67076167076168**：全部复赛 train 上新训 H1、官方 OpenAI CLIP ViT-B/32、匹配 **336×336** 输入、末八块 AC 14 轮、唯一 checkpoint 的中心图+水平翻转双视图 logits 等权平均。相对 C3/224 双视图 57.8009828009828 高 **3.86977886977888 分**，但两者同时改变了训练分辨率与全量模型，不能把全部收益归因于 TTA；见 `docs/120` §6A–6C 和提交台账。
- 组委会群聊已答复：同一冻结 checkpoint、同一测试图像、确定性多视图并聚合 logits 属于允许的单一推理流程；`docs/compliance_questions.md` C07 有既有截图来源。2026-09-25 用户再次转述了相同答复。**这不许可多个 checkpoint、模型融合、不同骨干集成或利用 test 选择视图/权重。**
- [赛题官网](https://www.aicomp.cn/tracks/tracks-1/3714.html)明确要求 **CLIP ViT-B/32 骨干不可替换**，允许在其基础上研究鲁棒损失、Adapter/LoRA 等；主要指标为 Top-1。赛题群对插值位置嵌入的 336 输入给出“骨干和预训练权重不变”条件下的回复（C21）。同学所说“换骨干/注意力/分辨率/损失函数都能提分”是研究线索，**不是每项必然提分的证据或规则豁免**。
- 禁止直接换成 ViT-B/16、Swin、DINOv2 等骨干，禁止改写原始 ViT-B/32 的内部注意力拓扑后仍声称骨干未变，禁止引入非官方预训练权重。可讨论保留原骨干、仅在其输出后增加小型可训练 token 注意力读出/Adapter；实施前先问组委会这一精确边界（C23），并只在复赛 train 派生折验证。

## 3. 执行队列：每次只动一个主要变量

### P0：C6/336 单 checkpoint 的固定多视图 TTA（先做）

1. 先用现有 C6/336 折内 checkpoint 与各自**未参与训练**的复赛 train 验证分区，复现两视图基线；核对中心视图与训练期指标及 checkpoint/折哈希。旧折和第三折可用，但第三折与旧验证集约有 19%–20% 样本重叠，相关性必须披露，不能冒称三折独立。
2. 在看到新结果前冻结**一个**四视图候选及等权 logits 聚合，例如原生 336 中心/水平翻转，加一个轻微固定缩放裁剪及其水平翻转；只允许确定性预处理、同一 checkpoint、无测试集反馈。缩放和裁剪的精确像素、插值、视图顺序及哈希写入独立预注册，不能在验证后挑视图。此前 C3 的四视图方案可作参照，但不是 C6 通过的证据。
3. 与 C6 双视图做样本配对比较：Top-1 为主，macro、尾类类均、按支持数分桶和逐类零召回为诊断；用近重复组配对 bootstrap 报增益区间。建议前瞻性晋级阈值为**至少两个折总体 Top-1 均 ≥ +0.30 pp、组配对区间下界为正，且 macro/尾类无预先定义的重大崩塌**。少数类由“答对一张→零张”只报告、不再单独一票否决；若整个尾部大幅塌陷则止损。最终阈值在运算前冻结。
4. 只有晋级后才锁定唯一 C6 全量 checkpoint 和 TTA 协议，对 Stage2 test 做一次新协议推理并另建提交包；现有 61.6708 分包保持不动。不得通过线上结果反选视图权重。预计验证占用几十分钟级 GPU、无需新训练；实施前以实际样本量冒烟重新报价。

### P1：输入分辨率/patch 网格的单变量实验

1. 在相同复赛 train 派生折、H1 训练程序、PEFT 末八块/AC/epoch/seed 与双视图协议下，首先只比较 **320×320 vs 336×336**；320 恰好是 10×10 个 32 像素 patch，避免 336 右/下侧 16 像素被忽略，但也减少输入细节，**不预设其更好**。位置嵌入从官方 7×7 插值，骨干结构和官方权重不变。
2. 当前分辨率适配代码仅允许 336；320 必须先补独立实现、官方权重/参数名不变的回归测试及小批量预处理验收，再重新提取冻结特征、训练折内 H1 和匹配分辨率 PEFT。复用的只能是相同 Stage2 train 派生数据和代码，不能拿已训练的 336 H1/视觉权重充数。先单折短筛，再至少一折同环境确认；若 320 明显不优，立即止损。352 或更高分辨率仅在记录 320 结果、确认显存/耗时可行后新立预注册，不同时扫一串尺寸。
3. 建议验证晋级为同配对折 Top-1 稳定 **≥ +0.50 pp**，组配对区间支持正向，macro/尾部无重大崩塌；新全量模型只在晋级后从官方权重与全新全量 H1 训练。预计是**小时级本机 GPU 实验**，具体耗时和新增磁盘以 1 轮基准测试为准，不把旧 336 成绩或在线分数当作选择尺。

### P2：鲁棒损失函数消融

1. 先检查现有 `src/aictrack1/methods/gce.py`、`elr.py` 与 `scripts/train_peft.py` 的损失/AC 状态更新接口，并补单元测试。当前 PEFT 使用加权 CE；已有模块不代表已经接入该训练路径。冻结一项替代损失（优先 GCE）及超参数，不做多参数网格。
2. 在固定 336、H1、末八块、数据折、seed、训练日程及 AC 权重机制下，**只替换每样本基础损失**并与原 AC+CE 比较，保持有效质量计算口径一致；另行记录损失与 AC 联动，必要时下一轮才做交互消融，避免同时改变采样、损失、阈值。GCE/ELR 只使用本阶段 train 状态。
3. 比较 Top-1、macro、tail、支持数分桶、零召回、每类权重均值与 sum(weight)、有效训练质量和噪声冲突组；若尾类被损失与 AC 双重压低，停止该方案。至少一折正向后再同环境第二折确认，全量重训只给通过方案。

### P3：保持 ViT-B/32 不变的轻量注意力读出（暂缓）

1. 用户 2026-09-25 明确要求注意力机制先按赛题规则执行。因此**目前不改原骨干内部注意力，也不启动新增注意力读出实验**；P0–P2 不依赖本项咨询。仅当以后决定启用附加读出时，才向组委会精确确认：保留 OpenAI 官方 ViT-B/32 的 patch embedding、Transformer 注意力层、层数/宽度和初始权重不变，**仅在输出 patch tokens 后附加一个小型可训练注意力池化/分类读出并最终只保留一个模型**，是否仍属允许的微调/Adapter？在明确答复前不将其作为正式提交路线。
2. 若允许，先在冻结 C6/336 特征上做容量匹配的线性头 vs 注意力读出诊断，确认增益不是单纯参数数目/训练时长带来的；随后再做同折、同日程 PEFT 单变量比较。优先保留原 CLS 路径并对新读出做残差式小幅修正，以降低噪声小类过拟合风险。
3. V2 patch 均值试验只说明**均值读出**无充分晋级证据；不应据此排除 learned attention，也不能把“换原骨干内部注意力”混同于“附加读出层”。若组委会不允许，P3 直接取消。

## 4. 排序、预算与停止/出包门槛

- 优先顺序为 **P0 TTA → P1 分辨率 → P2 损失**；P3 注意力读出暂缓，待明确合规咨询及用户再批准后才考虑。P0 低成本、可在现有 61.67 分模型上检验；P1 有最大既有正证据但需重训；P2 评估噪声学习的模型上限。GPU 训练仍串行、使用原子锁。
- 当前只批准制定计划，**不沿用 9 月 25 日已结束批次的 7–9 小时授权自动开新一批训练**。开跑前按 `AGENTS.md §7.1` 报告每批 GPU/CPU 时长、显存/磁盘增量、截止时点、回滚与完整 checkpoint 策略，取得本批确认；不得连接已停机 L20。
- 主指标是官方 Top-1；macro、tail、有效质量和零召回用于发现不可接受的系统性退化，不再用“任意一类零召回新增”否决总准确率明确进步。前瞻性阈值在各试验开跑前锁定，不追改 `docs/115`–`docs/118` 的历史判决。
- 每一轮仅访问 Stage2 train 派生验证集选方向；仅当方案通过事先门槛、完成全量 Stage2 train 的新模型训练（纯 TTA 除外）、锁定唯一 checkpoint 和推理协议后，才对 test 生成一个新包。每日提交次数珍贵；最多推荐一个验证最充分的包，由用户自行提交并回报分数。线上分数只记台账，不用于回头调整同批协议。
