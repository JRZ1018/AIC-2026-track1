## 1. 背景与两个问题

`docs/56` 记录 C 候选（lr `1.75e-6` + classwise history，`min_weight=0.2`）线上 **59.6107**，
比 lr1.5e-6 纯 CE 的 58.8577 高 **+0.7530**。固定验证三项指标同时提升
（Top-1 +0.005559、macro +0.005545、冲突 +0.003976）。

但该候选中**同时改变了两个变量**（学习率 1.5e-6→1.75e-6，且新增软权重），
因此尚不知道收益来自哪一个。本批回答两个问题：

1. **方向 2（归因）**：把学习率固定回 1.5e-6，只加 classwise history——软权重本身是否独立有效？
2. **方向 1（参数搜索）**：在 1.75e-6 + cwh 上把软权重下限从 `min_weight=0.2` 放松到 `0.35`，
   是否更好？（`docs/52` §8.2 已预置该分支）

## 3. 归因判据（不涉及门禁，只做解释）

设 lr1.5e-6 纯 CE 的 seed1 为 `B15 = 0.705517292`（Top-1）、
lr1.75e-6 纯 CE 的 seed1 为 `B175 = 0.706632435`、
lr1.75e-6+cwh 的 seed1 为 `C175 = 0.711286724`。

| 观测 | 结论 |
| --- | --- |
| D 显著高于 `B15`（例如 ≥ +0.003） | 软权重**独立有效**，是收益主因；学习率只是次要因素 |
| D 仅小幅高于 `B15`（< +0.001） | 软权重单独作用有限，收益主要来自"高学习率 + 软权重"的交互 |
| D 低于 `B15` | 软权重在低学习率下无效，必须与高学习率配对 |

三种情形都不改变后续流程，只决定下一轮把算力投向"软权重参数"还是"学习率 × 软权重交互"。

## 4. seed1 门禁（沿用未修改的门槛）

基线为已验收的 T2 last4 / lr1.5e-6 seed1：Top-1 `0.705517292`、macro `0.705408096`、
冲突子集 `0.308813781`。

候选进入多种子确认必须**同时**满足：

| # | 条件 | 阈值 |
| ---: | --- | --- |
| 1 | 最佳固定验证 Top-1 | **严格高于** `0.705517292` |
| 2 | macro accuracy | **不低于** `0.705408096` |
| 3 | 冲突子集 Top-1 | **不低于** `0.308151096` |
| 4 | 最佳结果不是单 epoch 异常尖峰 | 需 epoch 曲线支撑 |
| 5 | 指标全部有限 | 无 NaN / Inf |
| 6 | 哈希一致 | config、输入、初始化器、checkpoint、commit |
| 7 | 未访问 test | `scope` 声明且 `command.txt` 无 test 引用 |

### 选择规则

1. 先排除保护指标（第 2、3 条）失败者；
2. 合格者按 Top-1 从高到低排序；
3. **最多晋级两个**；
4. 若无候选通过，方向 1 与方向 2 均记为负结果，转入方向 4（8 epochs）与方向 3（叠加）；
5. 结果出来后不得修改门槛。

### 附加停止线（针对 E）

E 与已通过门禁的 `C175 = 0.711286724` 比较：若 E 的 Top-1 **低于 `C175` 超过 0.003**
且冲突子集也低于 `0.312789937`，则判定"放松下限有害"，停止 `min_weight` 向上搜索，
不再测试 0.5。
