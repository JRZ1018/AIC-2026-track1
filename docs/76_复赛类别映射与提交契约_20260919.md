# 复赛类别映射与提交契约

日期：2026-09-19（Asia/Shanghai）

状态：**B02 已完成**。本文记录复赛数据到手前完成的通用化工程，不代表复赛真实类别格式、
test 目录结构或提交首列格式已经确认。正式 Stage 2 配置仍保持 `contract_confirmed: false`。

## 1. 解决的问题

初赛代码包含三个只适用于当时数据的假设：

1. 类别 ID 必须匹配四位数字；
2. test 图片必须全部位于根目录；
3. 训练目录名可以直接排序后作为官方 ID。

这些假设已经从通用代码中移除或改为显式配置。复赛不再因为 `10001`、`cls_001`、中文 ID
或嵌套 test 目录而在代码层面必然失败，也不会在 basename 冲突时静默覆盖预测。

## 2. 类别映射规则

类别合法性的第一层、也是始终启用的规则，是**精确属于显式 `ClassMapping`**。映射要求：

- `official_class_id` 是非空字符串；
- 不含首尾空白、NUL、CR 或 LF；
- 官方 ID 唯一；
- internal index 唯一且从 0 连续；
- 映射摘要包含 internal index、官方 ID 和 class name。

第二层是可选语法约束：

```yaml
submission:
  official_class_id_pattern: '\d{4}'
```

只有复赛正式规则明确类别 ID 语法时才填写该正则。`null` 表示不猜测格式，只按显式映射
成员关系校验。空正则、无效正则和能匹配空字符串的正则会在配置加载时失败。

`ClassMapping.from_train_directories(...)` 现在默认接受安全的任意目录名；仅在调用方明确传入
`official_id_pattern` 时做语法限制。`scripts/derive_class_mapping.py` 从数据配置读取这一可选约束。

### 2.1 数据到手后的映射决策

按以下顺序决定，不得凭排序猜测：

1. 若官方数据提供目录名到官方 ID 的映射文件，使用 `class_mapping_provenance: official_file`，
   原样读取并验签；
2. 若官方书面规则明确“训练目录名就是最终官方 ID”，审计目录名后才可改用
   `train_directory_names` 并派生显式 CSV；
3. 若目录是类别名称而官方 ID 来自另一文件，必须建立显式对应关系，禁止按字典序或出现顺序
   隐式编号；
4. 任何重复、缺失、无法一一对应或格式来源不明都停止，不进入训练和出包。

Stage 2 模板当前采用最保守的 `official_file` 占位；真实压缩包审计后再替换路径和 provenance。

## 3. test 路径与提交首列

数据配置新增明确模式：

```yaml
submission:
  filename_mode: basename      # 或 relative_path
```

| 模式 | 输入 manifest 示例 | CSV 首列 | 适用条件 |
|---|---|---|---|
| `basename` | `folder/a.jpg` | `a.jpg` | 官方只要求文件名，且所有 basename 唯一 |
| `relative_path` | `folder/a.jpg` | `folder/a.jpg` | 官方明确要求保留相对路径 |

两种模式共同拒绝：

- 空路径、绝对路径、`.`、`..`、空路径段和控制字符；
- 输出键在大小写不敏感比较下发生冲突；
- prediction key 与预期 key 的缺失或额外项；
- CSV 中重复、乱序、额外或缺失文件。

`basename` 模式遇到 `folder-a/x.jpg` 与 `folder-b/X.JPG` 会在推理前硬失败。系统不会擅自选一个、
覆盖预测或自动切换为相对路径；必须根据官方格式修改配置后重新验收。
