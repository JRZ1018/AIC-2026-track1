# 获奖导向总体工作计划（初赛官方数据阶段）

更新时间：2026-09-13（Asia/Shanghai）

## 1. 文档定位与当前结论

本文件是项目唯一的总体执行计划。动态上游方案以 `docs/04_上游方案调研与复用登记.md` 为准，具体实验事实以对应报告和 `experiments/index.csv` 为准；本文件只维护阶段判断、优先级、门禁和止损条件。

项目已经从“无官方数据阶段”切换到**初赛官方数据阶段**，后续不得再以合成数据或目录模板代替真实数据结论。当前状态是：

- 初赛训练集 103,218 张、500 类，测试集 24,967 张；全部图片可解码。
- 训练类别近似均衡，每类 201–213 张，因此初赛不应把主要预算押在长尾校正上。
- 已固定重复簇隔离的 82,592/20,626 训练/验证划分。
- 发现 1,032 个跨标签精确重复哈希，共涉及 2,095 个训练样本；这只能证明结构化标签冲突，不能直接当作完整噪声率。
- OpenAI 官方 CLIP ViT-B/32 冻结特征缓存和 A0/A1 已完成；后续公平优化复验中 H1 线性 Adam 三种子均值为 68.6916%，现作为最强冻结特征参考。旧 A0 的 30.1319% 仅是欠优化下界。
- A1 在验证集跨标签精确冲突子集上的 Top-1 为 30.0199%，在其余验证样本上为 70.9002%，说明后续方法必须关注结构化冲突而非只追求训练拟合。
- S1 本地模拟提交闭环、A2/A3、端到端 PEFT 和 M1 三种子配对复验已完成。M1 平均仅领先 M0 v2 0.0695 点，未达到预注册的 0.10 点门槛，停止扩张；H1 线性 Adam 仍是更强参考。

当前关键路径不是重新建立基线，而是：

1. 继续以初赛固定验证和线上 Top-1 追分；初赛与后续阶段任务和指标高度一致，仍是算法效果的主要代理证据。
2. 停止收益递减的 LoRA rank/alpha/相邻层数微调，把主训练预算提升到有约束的末块/多块部分解冻，并用学习曲线决定是否延长优化。
3. 为所有强候选增加复赛迁移门禁：动态类别数、线性扩展状态、head/mid/tail 诊断、确定性长尾压力测试、完整断点恢复和从头复现。
4. 候选先单 seed 筛选，再做三种子和从头复训；锁模后才读取测试图片、生成提交并用线上分数做稀疏确认。

## 2. 硬约束与工作原则

赛事原文、两份本地规则和根目录 `AGENTS.md` 的约束全部适用，尤其是：

- 骨干只能使用 OpenAI 官方权重的 CLIP ViT-B/32。
- 每阶段只能使用该阶段官方数据，不得引入额外图像、标签、类描述或人工补标。
- 测试集只能用于最终推理，不得用于训练、统计、阈值选择、Prompt 优化、BatchNorm 更新或任何适配。
- 最终必须是一份 checkpoint、一套标准图像前向和一个预测结果；不得集成、投票或多模型融合。
- 自动筛样和标签处理必须由提交代码直接复现；人工检查只用于格式理解和故障排查。
- 任何大量占用 GPU、CPU、内存或磁盘 I/O 的任务，必须按 `AGENTS.md` 先报告预算并取得本轮明确批准。

官方主指标为 Top-1 Accuracy。所有正式选型以固定验证集 Top-1 为第一判据，以 macro accuracy、每类召回、冲突子集、校准和方差作为诊断，不用辅助指标替代主指标。

## 7. 验证协议与噪声诊断

- 主选择集固定为官方训练集派生的 20,626 张 noisy validation，不因结果反复重划。
- 跨标签精确重复簇必须保持隔离；任何新划分逻辑都要验证没有簇泄漏。
- 全体验证 Top-1 是唯一主选型指标；冲突子集和非冲突子集只作诊断，不能删掉冲突样本后宣称主成绩。
- 初筛使用一个固定种子；候选进入最终路线前运行不少于 3 个种子，报告均值、标准差和最差值。
- 最终候选从 OpenAI 官方权重重新训练至少一次，不直接采用调参过程中偶然最好的 checkpoint。
- 验证集不参与原型、阈值、校准统计的拟合；若某项诊断需要拟合，必须只用训练部分并把逻辑写入配置。

晋级建议门槛：单种子相对强基线至少有可重复的绝对 Top-1 改善，且 macro、最差类和非冲突子集没有不可接受退化；微小差异必须进入三种子后才可宣称有效。

## 8. 提交与排行榜防过拟合

- 正式提交文件只能由脚本生成，固定命名 `pred_results.csv` 后压缩为 ZIP。
- 测试文件名必须逐字匹配，类别为四位数字；表头等细节以最新正式通知/报名系统为准。
- 每次提交记录唯一变化、预期、失败回退、Git commit、配置哈希和 checkpoint 哈希。
- 每日次数未确认前，预算按 20% 管线/基线、40% 关键方法、20% 最终复核、20% 故障回退分配。
- 线上分数只提供稀疏证据，不允许用测试图片、提交顺序或多次榜单反馈反推标签。
- 第一次真实测试推理必须在候选和提交格式均锁定后，按系统资源门禁另行申请批准。

## 9. 资源策略

已有实测可作为后续估算基线：

- 全量 103,218 张训练图的冻结特征缓存为 103,218×512 float16，26 个分片，约 116.3 MiB。
- 全量提取耗时 264.64 秒，平均 390.03 张/秒，峰值已分配显存约 614.69 MiB。
- A1 分类头训练约 22.79 秒，相关产物约 29.6 MiB。

因此 A2/A3 应优先复用缓存完成廉价筛选。PEFT 属于新的资源档位，必须通过短程实测重新估算，不得套用冻结特征耗时。全程遵守：

- AMP、梯度累积、必要时梯度检查点；不并行争抢单卡显存。
- 不做无边界大网格搜索；轻量候选用短程淘汰，主要训练预算用于预注册的 T2 部分解冻、多种子和从头复现。只有验证最佳点仍在末 epoch 且遗忘诊断稳定时才增加训练轮数。
- 产物写入被 Git 忽略的 `artifacts/`，轻量指标和结论写入 `experiments/` 与文档。
- 截止前至少预留 24 小时用于最终复训、推理、校验、上传失败和回退。

## 10. 分赛段策略

### 初赛：方法实验室

建立有效提交、冻结鲁棒损失、唯一 PEFT 强基线和 M1–M3 主线，校准本地验证与榜单关系。近均衡数据不优先做长尾专用模块。

### 复赛：40% 权重，首次正式争奖

从 OpenAI 官方权重和复赛数据重新开始，不复用初赛数据或其训练统计。按 2026-09-13 官网现行规则，复赛为 750 类、148,695 个训练样本并存在长尾；重点验证类别感知阈值、先验校正和 head/mid/tail 诊断，前半程完成强基线，后半程只优化已在初赛证明有效且通过迁移门禁的主线。

### 半决赛：60% 权重，稳定与复现优先

再次从官方权重和半决赛数据重新开始。原则上不大规模换轨，只校准少量阶段相关超参数；提前完成代码、模型、报告和演示材料的复现演练。

### 总决赛：用证据链解释方法

围绕“普通微调为何记忆噪声、全局 small-loss 为何伤害难类、类感知多信号可信度和表征锚定为何有效”组织消融、失败案例、训练曲线和复现实证，不夸大未验证结论。
