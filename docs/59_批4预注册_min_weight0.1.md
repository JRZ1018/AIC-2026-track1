# 批 4 预注册：min_weight=0.1（下限向下搜索）

日期：2026-09-16
上游证据：`docs/58_批3预注册_mw50与8epochs延长.md`，以及批 2 的 `min_weight` 扫描结果

## 1. 依据：min_weight 扫描呈单调递减

在 lr `1.75e-6`、classwise history、6 epochs、seed `20260910` 的固定条件下：

| `min_weight` | Top-1 | macro | 冲突子集 | 实验目录 |
| ---: | ---: | ---: | ---: | --- |
| **0.20** | **0.711286724** | 0.711163759 | 0.310139179 | `20260916-c-…cwh-6ep-seed1` |
| 0.35 | 0.709929228 | 0.709817827 | 0.310801864 | `20260916-e-…mw35-6ep-seed1` |
| 0.50 | 0.708571732 | 0.708452821 | 0.309476465 | `20260916-f-…mw50-6ep-seed1` |

**Top-1 随下限升高单调下降**（每次约 −0.0014）。这说明"降权越温和越好"，
即当前噪声下不应过度压制样本权重。该趋势指向的方向是**下限更低**，而非更高。

因此批 3 的 `min_weight` 向上搜索（0.5）已由 F 的负结果终止，
本批改为向下测试 `min_weight = 0.1`。

## 3. seed1 门禁（沿用批 3 新基线）

基线为已通过三种子门禁且线上最佳的 C 候选 seed1：

| 指标 | 基线 | 阈值 |
| --- | ---: | --- |
| Top-1 | `0.711286724` | **严格高于** |
| macro | `0.711163759` | 不低于 |
| 冲突子集 | `0.310139179` | 不低于 |

其余条件：非单 epoch 尖峰、指标有限、哈希一致、未访问 test。

### 选择规则

1. 先排除保护指标失败者；2. 按 Top-1 降序；3. 最多晋级两个；
4. 若 H 的 Top-1 未超过 C 基线，则判定 `min_weight` 已在下限 0.2 附近取到最优，
   **停止整个 min_weight 扫描**，不再测试 0.05 等更低值（避免无依据的网格扩张）；
5. 结果出来后不得修改门槛。

### 说明

若 H 通过，则进入 seed2/seed3（同一 commit）；若 H 未通过，本轮 `min_weight` 方向
以"0.2 为最优点"正式收口，后续算力转向其他机制。
