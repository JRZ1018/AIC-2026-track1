## 2. 当前证据与战略判断

### 2.1 初赛成功路线应继续，但只作为锚点

初赛最终 61.8016 的主要成功路径是：重新训练 H1、冻结头、解冻末四块、较低学习率、AC 软加权、
降低 `min_weight`、引入全局损失量级混合并适度延长训练。这个方向在复赛已经得到部分复现：

- Stage2 H1 固定验证 Top-1 为 `0.644718707`；
- last-4 CE 最佳为 `0.672999978`，比 H1 高约 2.83 个百分点；
- last-4 AC 最佳为 `0.684937954`，又比 CE 高约 1.19 个百分点；
- AC 的 16 个 epoch 有效训练质量均为 L1，没有发生尾类有效质量塌陷。

因此，以下知识继续使用：

- OpenAI 官方 CLIP ViT-B/32 + Stage2 新 H1；
- 冻结头、部分解冻视觉块；
- 小学习率、batch 64、wd 0.01、梯度裁剪 1.0；
- AC 的代码与超参数可作为搜索中心；
- 先短筛、再多种子、最后全量单模型复训的实验纪律。

不能复用初赛训练出的头、视觉权重、optimizer、特征、样本历史、阈值、类别统计或提交预测。

### 2.2 不能继续只沿初赛配方做大规模训练

当前固定验证最佳约 68.49%，线上只有 56.50%，绝对差约 12 个百分点。这个差距说明：

1. 复赛 train 长尾而 test 均衡，固定验证仍继承 train 的长尾分布；
2. 固定验证单次小增益未必能转化为线上增益；
3. 初赛最优学习率、解冻深度、`min_weight` 和训练长度在 Stage2 未完整重搜；
4. 继续只在 `min_weight=0.02` 附近长训，预期收益递减且可能放大过拟合。

所以一周资源采用约 `40%` 继续校准已验证主线，约 `60%` 投向复赛特有的新方向。

### 2.3 已经证伪或低优先级的方向

以下方案不得原样重复：

| 方向 | Stage2/Stage1 证据 | 本周处置 |
|---|---|---|
| PEFT 期间 `count^-0.5` 类均衡采样 | Stage2 epoch8 Top-1/macro 均低于自然采样 | 停止原参数；不扩大幂指数网格 |
| train prior logit adjustment `tau=0.5` | Stage2 未过门禁 | 停止原参数；不做连续 tau 扫描 |
| AC tail mean floor 0.35 | Stage2 Top-1/macro 明显下降 | 停止原保护强度 |
| AC min effective mass 4.0 | Stage2 Top-1/macro 明显下降 | 停止原保护强度 |
| 视觉原型软降权 | 初赛固定验证未过门禁且冲突子集下降 | 不原样复活 |
| GCE、LogitClip | 初赛冻结特征/头路线明显弱于 CE | 不进入本周主线 |
| ELR | 上游登记已按 P3 门禁排除 | 本周不重启；若要重启须先更新登记与依据 |
| Label smoothing 0.05 | 初赛整体 Top-1 和校准变差 | 不重复 |
| LoRA 大网格 | 初赛最终明显弱于 last-4 路线 | 不作为本周主线 |
| 盲目增加 batch 至 128/256/512 | L20 实测仅小幅提速且短程指标下降 | 正式实验固定 batch 64 |
| 双网络、模型融合、种子平均、投票 | 与单模型规则边界冲突 | 禁止 |

### 2.4 本周最值得验证的新问题

按预期收益与实现风险排序：

1. **Stage2 学习率与解冻容量重新校准。** Stage2 只验证了初赛最优点，没有证明它仍是复赛最优。
2. **AC 重新校准。** 直接比较更保守的 `min_weight` 和损失混合比例，不叠加尾类硬保护。
3. **分类头与均衡 test 的错配。** PEFT 期间均衡采样失败，不代表“先训练一个更均衡的 H1，随后冻结它”也失败。
4. **表征/权重锚定。** 用 L2-SP 类的权重保持约束抑制视觉块偏离官方 CLIP 初始化，直接针对泛化落差。
5. **完全相同图片的冲突标签。** Stage2 有 1,877 个跨标签精确冲突组、3,884 个样本；自动、可复现地降低互相矛盾梯度可能比泛化筛噪更直接。
6. **温和增强或 MixUp。** 当前训练增强只有随机裁剪与水平翻转；若前述路线都无增益，再测试一个保守增强变量。

## 3. 统一实验协议

### 3.1 不可变条件

- 仅使用 Stage2 官方 train；test 不参与训练、统计、阈值、选模或自适应；
- OpenAI 官方 CLIP ViT-B/32 原始权重，SHA-256 保持既有验签值；
- 固定 split `118,958 / 29,737`，无重复簇跨侧泄漏；
- 正式短筛以 Stage2 H1 fixed `best.pt` 为共同初始化；
- batch 64、wd 0.01、clip 1.0；
- L20 运行参数固定为 workers 16、prefetch 4、persistent workers；
- 每轮只改变一个主要算法变量；
- 每个运行使用独立 run ID、配置、日志、checkpoint、退出码和环境记录；
- 多种子只用于验证稳定性，最终不得平均、融合或投票。

### 3.2 指标与选模口径

官方指标仍是 Top-1。由于复赛 test 类别均衡，而本地 validation 继承长尾，固定验证同时报告：

1. overall Top-1；
2. macro accuracy；
3. head/mid/tail accuracy；
4. 零召回类数；
5. 最差类召回与召回分位数；
6. 训练/验证 loss、最佳 epoch 和末轮退化；
7. AC 候选额外报告每类平均权重、每类 `sum(weight)`、有效/原始质量比与 L0/L1/L2；
8. 精确冲突子集与非冲突子集指标，只作诊断，不单独替代官方 Top-1。

新增一个只读的“均衡验证视图”：从现有固定 validation 按类等权计算 macro，并可生成每类固定上限的
诊断子集。它不创建新 split、不重新训练、不读取 test，也不能事后改变。最终晋级仍要求 Top-1、
macro 和 tail 联合通过，不能只优化某一个辅助指标。

### 3.3 短筛门禁

R3 同 seed 的 epoch8 参考：Top-1 `0.679860115`、macro `0.671815040`、tail `0.670845389`、
零召回 4。

8-epoch 候选的基本晋级条件：

- 无 NaN/Inf、数据和 provenance 门禁通过；
- Top-1 不低于 `0.678860115`；
- macro 不低于 `0.670815040`；
- tail 不低于 `0.669845389`；
- 零召回类不超过 4；
- AC 有效质量不得达到 L2；
- 若相对参考的 Top-1 提升小于 0.2 个百分点，只视为“待确认”，不得宣称有效。

优先晋级满足以下任一条件且其他指标不退化的候选：

- Top-1 提升至少 0.2 个百分点；
- macro 提升至少 0.2 个百分点且 Top-1 不下降；
- tail 提升至少 0.3 个百分点且 Top-1/macro 下降均不超过 0.1 个百分点。

### 3.4 多种子确认门禁

- 只对最多两个短筛胜者补 seed `20260922`、`20260923`；
- 三个 seed 与各自配对基线比较，不拿不同初始化制造伪增益；
- 三 seed 平均 Top-1 至少提高 0.2 个百分点；
- 三 seed 平均 macro 不下降；
- 任一 seed 的 Top-1 不得下降超过 0.25 个百分点；
- tail 不出现系统性下降，零召回类不增加；
- 未通过则停止，不启用全量配置。

门槛在执行前冻结。如果首日复核发现历史基线的随机性估计不支持这些数值，只能在任何新结果产生前
修订并记录理由。

## 4. 七天执行计划

“Day 1”从负责人批准实际执行之日开始，不强绑定自然日期。需要 L20 的日期会在启动前单独通知，
披露预计时间、磁盘增量、中断/恢复能力，并等待开机与本次资源批准。

### Day 1：台账修复、评估冻结与低成本头部实验

目标：先解决“我们是否在用正确代理指标选模”，同时完成不需要 L20 的便宜实验。

工作：

1. 重建 `experiments/index.csv`。当前 137 行中 Stage2 行数为 0，先修索引提取/发现路径并补齐
   R1–R5；不得伪造旧环境字段。
2. 把 R2/R3/R4/R5 的逐 epoch 曲线整理成统一对照，确认 R3 峰值在 epoch14、epoch16 是否已回落。
3. 固化均衡验证视图、指标输出和晋级脚本，并补回归测试。
4. 检查 H1 训练器，增加两种只作用于 H1 阶段的温和方案：
   - H1-B：按 `count^-0.5` 抽样或等价的温和类权重；
   - H1-E：effective-number 或 inverse-sqrt 类权重，二者只选一个实现，避免重复。
5. 在冻结 CLIP 特征缓存上训练 H1-N/H1-B/H1-E。该步骤成本低，按 Top-1、macro、tail、
   零召回类和稳定性选出至多一个新 H1。

停止线：若新 H1 不能提高 macro/tail，或 Top-1 下降超过 0.2 个百分点，不进入 PEFT。

资源：优先本机；预计 2–4 小时工程与验证，GPU 高占用时间很短或不需要 L20。

### Day 2：复赛主线再校准——AC 两个单变量

目标：回答初赛最优 AC 参数在 Stage2 是否仍处于合理区域。

候选：

- A1：基线 AC，只改 `min_weight: 0.02 -> 0.05`；
- A2：基线 AC，只改 `magnitude_mix: 0.75 -> 0.50`。

两个候选均为 8 epochs、seed `20260921`。若 L20 受控双任务并行试验已通过资源门禁，则以两个
独立 batch-64 作业并行；否则串行。不得把 A1/A2 叠加。

结果分支：

- 两者都失败：冻结 `0.02/0.75`，本周停止 AC 参数微调；
- 只有一个通过：补两个 seed；
- 两者都通过：按联合门禁排序，至多保留一个补种子，避免在同一家族继续扩网格。

资源：L20 约 30–60 分钟训练墙钟时间，另加打包、传回和验收；服务器不用时立即关机。

### Day 3：视觉优化重新校准——学习率与容量

先跑学习率，后跑容量，不在同一个候选同时变化。

第一对候选：

- L1：last-4 AC，lr `1.25e-6`；
- L2：last-4 AC，lr `2.25e-6`。

参考点为 `1.75e-6`，其余配置不变。两个边界均失败则停止学习率轴；某一边明显更好时只向该方向
追加一个点，不做全排列。

容量为条件任务：仅当学习率轴没有明显胜者，或胜者已确认后资源仍允许时再跑：

- C1：last-2，保持已选学习率；
- C2：last-6，保持已选学习率。

last-2/last-6 都从官方 CLIP + 同一 Stage2 H1 开始，不从 last-4 checkpoint 续训。

资源：L20 约 1–2 小时；优先两任务受控并行。Day 3 最多完成两组候选，不连续扩大搜索。

### Day 4：新主线——权重锚定，条件补做 H1 路线

目标：针对固定验证与线上之间的泛化落差，抑制可训练视觉参数偏离官方 CLIP 初始化。

工程任务：

1. 实现仅作用于可训练视觉参数的 L2-SP/weight anchoring；
2. 锚点是本次 Stage2 训练开始时加载的 OpenAI 官方 CLIP 参数，不是初赛或其他候选权重；
3. checkpoint 保存锚定系数、锚点来源哈希和恢复状态；
4. 系数为 0 时必须与现有训练逐步数值等价；
5. 单测覆盖 AMP、恢复、只约束可训练参数和参数组。

短筛先用小样本校准正则量级，再冻结两个系数，例如低/中两个数量级。正式 8-epoch 候选与当前
最佳 AC 基线相比只增加锚定项。

若 Day 1 有 H1 候选通过，则 Day 4 的第二个任务改为：新 H1 + 原基线 last-4 AC，回答“头部先验
是否能迁移到 PEFT”；不得同时叠加锚定。

资源：本机 2–4 小时开发/测试；L20 约 30–60 分钟短筛。

### Day 5：复赛特有噪声——精确冲突组的自动处理

目标：处理 1,877 个跨标签完全相同图片组所产生的确定性矛盾梯度。只使用 Stage2 train 自动生成的
hash 和标签，不人工改标签、不使用 test。

先做零 GPU 诊断：

- 统计冲突组在 head/mid/tail 的分布；
- 比较冲突样本与非冲突样本的 AC 权重、loss 与错误率；
- 检查相同像素是否可能来自合法多类别语义，避免直接硬删除。

诊断支持后，至多实现两个候选：

- X1：同一精确图片冲突组总损失归一化，使重复次数不放大梯度；
- X2：对冲突组使用其已观察标签集合的软目标，非冲突样本保持普通目标。

X1/X2 互斥。先做合成测试和小数据冒烟，再各跑 8 epochs。若冲突子集改善但 overall/macro 下降，
不得进入全量。若合规解释或实现语义不够清晰，则跳过 X2，只做 X1 或直接停止本路线。

资源：本机 2–4 小时；L20 约 30–60 分钟。

### Day 6：确认、组合与最后备选

任务按以下优先级执行：

1. 对全周最好的 1–2 个候选补足三种子；
2. 只有两个单变量都分别稳定通过时，才构造一个联合候选；
3. 联合候选必须再与每个单变量做消融，不能直接把所有有效项叠加；
4. 如果前五天没有任何候选通过，启动最后备选：保守 MixUp `alpha=0.2` 或温和颜色增强二选一，
   不同时加入，不做增强大网格；
5. 固定最终算法、学习率、解冻深度和 epoch。

优先允许组合的关系：

- 更优学习率 + 权重锚定；
- 更优 H1 + 已确认 AC；
- 权重锚定 + 已确认 AC 参数。

不优先组合：

- 类均衡 H1 + PEFT 类均衡采样；
- 冲突软目标 + 强 AC 降权；
- 多种长尾保护同时叠加。

资源：L20 约 1–3 小时，取决于晋级候选数量。若没有候选晋级，不为凑实验数启动服务器。

### Day 7：全量复训、提交与收尾

只对通过多种子门禁的方案进行全量训练：

1. 从 OpenAI 官方 CLIP 重新生成/核验 Stage2 全量特征；
2. 在全部 148,695 张 train 上重新训练唯一 H1；
3. 从官方 CLIP + 最终 H1 从头训练唯一 PEFT；
4. 训练长度优先使用固定验证最佳 epoch 附近。R3 当前最佳为 14，不能因为旧配置写了 16 就默认
   继续 16；若曲线证据支持，可在 14/16 中冻结一个，不根据线上分数事后选择；
5. 锁定唯一 checkpoint；
6. 对 test 只做一次推理，生成 `pred_results.csv` 和 ZIP；
7. 本地校验行数、文件名、顺序、类别集合、无表头契约和压缩包内容；
8. 记录 config、Git、环境、官方权重、H1、PEFT、CSV、ZIP 的 SHA-256；
9. 提交后只记录分数与候选身份，不根据 test 统计继续适配。

如果没有任何新候选通过，则不强行替换当前 56.4950 基线。可以把“同配方、固定验证最佳 14 epochs”
作为一次低风险全量复验候选，但必须在任务单中明确它只改变训练长度，且仍占用一次提交机会。

资源：L20 约 1–3 小时训练/推理/传回，取决于是否需要重建特征和最终方案复杂度。正式启动前重新估时。

## 5. 候选优先级与预算封顶

| 优先级 | 实验家族 | 最多正式短筛 | 进入多种子上限 | 理由 |
|---|---|---:|---:|---|
| P0 | AC 参数再校准 | 2 | 1 | 初赛/复赛均有正证据，成本最低 |
| P0 | 学习率再校准 | 2–3 | 1 | Stage2 未搜索，直接影响全部后续路线 |
| P1 | 解冻容量 last-2/4/6 | 2 | 1 | 初赛 last-4 成功但 Stage2 未复核 |
| P1 | H1 长尾适配 | 2 | 1 | test 均衡且训练长尾，头部路线成本低 |
| P1 | 权重锚定 | 2 | 1 | 直接针对泛化落差，单模型且合规 |
| P2 | 精确冲突组处理 | 2 | 1 | Stage2 特有、自动可复现，但语义风险较高 |
| P3 | 保守增强/MixUp | 1 | 1 | 前述路线失败后的备选 |

全周 8-epoch 正式短筛上限为 10 个，多种子家族上限为 2 个，全量训练上限为 2 个新方案。
超过预算必须重新审批，不能以“服务器还开着”为理由扩张。

## 6. L20 与本机分工

### 本机完成

- 代码、配置、单元测试和小样本冒烟；
- 冻结特征上的 H1 低成本训练；
- 指标汇总、哈希、索引和文档；
- 服务器断开后的结果验收与提交包归档。

### L20 完成

- 8/16 epoch 的 CLIP 部分解冻训练；
- 最终全量 H1/PEFT 与 test 推理；
- 两个已冻结独立候选的受控双任务并行。

### 并行原则

- batch 固定 64，不为占满 48 GiB 显存扩大 batch；
- 只有两个以上独立候选时才并行；
- 首次双任务并行先做 2-epoch pilot，记录总吞吐、单任务减速、GPU/CPU、峰值显存与错误率；
- 每项独立目录、日志、锁和退出码；
- 若双任务的单位时间有效实验数没有明显提高，立即回到单任务；
- 结果完成后第一时间传回 checkpoint、metrics、config、日志和哈希，确认本地完整后才允许停机。

服务器开机通知模板：

> 需要开启 L20。本次任务为两个独立 batch-64 的 8-epoch 候选，预计高占用 30–60 分钟，
> 磁盘增量预计 2–5 GiB，可中断并从 last checkpoint 恢复。运行前会确认公网 IP、磁盘与 GPU，
> 结束后先传回结果并验哈希，再通知关机。

## 7. 提交策略

复赛每天最多提交 2 次，但不把额度视为必须使用的配额。

1. 固定验证未过门禁的候选不提交；
2. 同一家族只提交一个锁定候选；
3. 每个提交在推理前冻结算法、checkpoint、命令和哈希；
4. 若一天有两个候选，优先选择机制不同的两个，而不是同一参数的邻近点；
5. 线上分只用于确认最终候选，不根据 test 预测分布、类别频率或错误样本继续调参；
6. 分数写入 `submissions/ledger.csv`，实验结果写入 `experiments/index.csv`，资源结论写入相应实验报告，
   不再混入 `docs/94` 的性能采样记录。

## 8. 每日收尾与停止条件

每天结束前必须完成：

- 训练进程为 0，或明确记录仍运行的 PID/任务；
- 远端新产物已传回本地并核对 SHA-256；
- `metrics.json`、配置、command、环境、Git 状态齐全；
- 实验索引已重建，报告写明通过/失败；
- 无数据、checkpoint、密钥或提交包进入 Git；
- 服务器是否可关机给出明确结论。

出现以下任一情况立即停止当前候选：

- test 被用于调参或统计；
- 数据 provenance、split、H1 或官方 CLIP 哈希不一致；
- NaN/Inf、有效质量 L2、零召回类异常增加；
- 两个实验同时改变多个主变量且无法归因；
- 训练已明显退化仍因“还有预算”继续；
- 远端产物尚未传回而准备释放实例；
- 需要突破本周 10 个短筛、2 个多种子家族或 2 个全量方案的预算。

## 9. 决策树

```text
Day 1 评估/索引/H1
  ├─ 新 H1 通过 → 安排一次“新 H1 + 原 AC”
  └─ 新 H1 失败 → 冻结自然 H1，不再调头

AC 参数 + 学习率/容量
  ├─ 有稳定胜者 → 多种子确认
  └─ 无胜者 → 保留 R3 配方，转权重锚定

权重锚定 / 精确冲突处理
  ├─ 单变量通过 → 与主线做一次受控组合
  └─ 均失败 → 最多测试一个保守增强候选

多种子确认
  ├─ 通过 → 全量重训 → 单次 test 推理 → 提交
  └─ 不通过 → 不替换 56.4950 基线，记录负结果
```
