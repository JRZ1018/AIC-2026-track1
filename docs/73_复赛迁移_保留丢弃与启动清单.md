## 2. 必须丢弃的 Stage 1 派生状态

“丢弃”指 **Stage 2 配置和训练不得引用**，不要求物理删除。历史文件继续保留用于审计。

| 对象 | Stage 2 处置 |
|---|---|
| 初赛 H1 分类头，包括全量头和固定划分头 | 不加载；在复赛特征上随机初始化并重训 Stage 2 H1 |
| 初赛 LoRA、部分解冻、优化器、调度器和 scaler 状态 | 不加载、不续跑、不作初始化 |
| `artifacts/audits/stage1/` 下的 manifest、split、类别映射和冲突表 | 在 `artifacts/audits/stage2/` 从官方复赛训练集重建 |
| `artifacts/features/stage1/` | 不复用；按复赛数据重新提取 |
| 逐样本置信度、EMA、ELR 目标、伪标签、loss 历史 | 全部从零初始化 |
| 初赛类先验、类别阈值、采样权重、校准温度和 logit adjustment | 只能从复赛训练部分重新估计 |
| 初赛 `expected_initial_top1` 和验证容差 | 在新的固定验证集上重新测定 |
| 初赛榜单和固定验证分数 | 仅作为方法假设来源，不作为复赛候选的晋级证据 |

在组委会明确书面确认“初赛微调权重可作为复赛初始化”之前，项目继续采用最保守解释：
**只从 OpenAI 官方 CLIP ViT-B/32 原始权重开始。**

## 3. 可以继承的抽象资产

- `src/aictrack1/**` 下的数据、模型、训练、评估与提交代码。
- OpenAI 官方 CLIP ViT-B/32 权重及其已审计 SHA-256。
- 可复现流程：配置、任务单、哈希清单、断点恢复、A/B 分工、私有产物回传。
- 方法假设：末块/多块部分解冻、约 `1e-6` 量级视觉学习率、动态软加权、
  `magnitude_mix`、固定验证与多种子确认。
- 初赛失败经验：固定验证分辨率有限，单种子差异小于约 0.2 线上点不能直接下结论；
  训练损失不能代替线上或干净验证泛化。
- 长尾诊断代码：head/mid/tail、macro、最差类召回、零召回类数、每类保留率。
- 合成夹具、提交格式校验器和治理检查器。

这些资产的“可继承”不意味着参数数值可直接沿用。初赛超参数只能作为搜索起点。

## 4. 数据到位前的准备边界

允许：

1. 建立 `DataSetStage2`、`configs/data/stage2*`、`artifacts/audits/stage2`、
   `artifacts/features/stage2` 和 Stage 2 实验命名规范。
2. 用合成数据验证 750 类动态映射、长尾划分、checkpoint 维度拒绝和提交校验。
3. 添加静态治理门禁，拒绝 Stage 2 配置引用任何 Stage 1 路径。
4. 在初赛训练部分构造的既有长尾压力环境中验证通用代码行为，但相关权重、阈值、
   统计量和 checkpoint 不得进入复赛。
5. 准备非执行型配置模板、实验预注册模板、报告目录和任务单模板。

禁止：

- 猜测复赛类别映射、文件数量之外的目录细节或标签语义。
- 创建看似可运行但填入虚构哈希、类别数或 checkpoint 的正式配置。
- 提前使用外部数据模拟复赛自然动植物类别。
- 为“占满算力”运行无门禁的大网格搜索。

治理检查必须拒绝 Stage 2 配置的路径字段中出现 `stage1` 或 `DataSetStage1`。当前静态

## 6. 复赛数据到位后的启动 runbook

### 6.1 只读审计

1. 记录官方来源、下载时间和原始压缩包 SHA-256。
2. 不修改原始数据；确认训练/测试目录和格式。
3. 扫描训练 148,695、测试 37,444、类别 750 的官方基准是否成立。
4. 记录坏图、文件扩展、每类数量、精确重复、近重复和跨标签冲突。
5. 测试集只做推理所必需的文件/格式审计，不统计预测相关信息。

数量或结构不符时立即停止，不自行“修复”官方数据。

### 6.2 重建索引与固定划分

1. 从复赛官方文件或已审计的训练目录重建显式类别映射；类别 ID 格式以复赛事实为准，
   不预设为四位数字，也不按未审计的目录顺序直接提交。
2. 生成 `artifacts/audits/stage2/train/samples.csv` 与数据摘要。
3. 以重复簇为不可拆分单位建立固定训练/验证划分。
4. 对尾类保证最低训练保留量；报告每类 train/validation 数量和零样本类。
5. 生成新的 `label_conflicts.csv`，不得复制初赛冲突表。

### 6.3 重建基线

按以下顺序，不跳步：

1. 单批次数据加载与 CPU/CUDA 冒烟。
2. 从官方 CLIP 原始权重重新提取复赛训练特征。
3. 随机初始化并训练 Stage 2 H1 冻结特征线性头。
4. 测量新的 `expected_initial_top1`，冻结固定验证守卫。
5. 建立 CE 的冻结头、末块/末四块部分解冻基线。
6. 再加入噪声软加权；只有真实分布触发长尾门槛时才加入长尾机制，保持单变量消融。
7. 锁模前不读取测试图像、不生成真实提交。

## 7. 复赛首轮实验优先级

首轮只保留三个有限搜索轴：

| 轴 | 起点 | 门禁 |
|---|---|---|
| 视觉容量 | 冻结 H1、末 2 块、末 4 块 | 固定验证 Top-1 与表征遗忘诊断 |
| 噪声鲁棒 | 关闭加权、初赛 AC 机制起点、加入类保留保护 | Top-1、冲突子集、每类有效权重 |
| 长尾处理 | 自然采样、温和均衡采样、训练先验校正 | macro、head/mid/tail、最差类和零召回类 |

执行顺序为单种子短筛 → 候选三种子 → 全量固定 epoch 复训 → 锁模 → 测试推理。
不同轴未经各自单变量验收不得直接叠加。

## 8. 长尾专项必须回答的问题

初赛原始训练集近似均衡；8 张/类桶类均召回 21.29%、31 个零召回类来自人为构造的
长尾压力训练集。该结果证明当前流程在严重类频偏斜下存在失效风险，但不能代表初赛真实分布，
也不能在复赛审计前证明以下每种机制都有收益。复赛数据到手后先实测每类支持数；长尾诊断为
首轮必做，以下算法机制仅在真实分布或训练期有效质量触发预注册门槛后解锁：

- 每类最低有效权重或最低保留量，防止尾类被全局高损失整体压低。
- 类感知阈值或降权上限，区分标签噪声与真实困难/稀缺类别。
- 自然采样与温和类均衡采样对照。
- 只基于复赛训练部分估计的类别先验校正。

最终选模仍以 Top-1 为主，但任何候选必须同时报告 macro、head/mid/tail、最差类、零召回类、
冲突子集以及每类有效训练质量。

## 9. 算力与协作纪律

- 复赛数据量约为初赛的 1.44 倍，任何正式训练都重新报告本机/B 机预算，不能直接套用另一台
  机器的耗时。
- 初筛串行执行；并发方案必须先证明数据解码、磁盘 I/O 和 CPU 不会成为相互污染的瓶颈。
- 新机器先做同配置、同种子的等价性实验；无法逐位一致时，明确唯一裁判机，禁止混用结果门禁。
- 所有正式训练继续遵守 `AGENTS.md` 的资源审批门禁。
- 每日最多两次线上提交；提交槽位优先用于已完成本地验收的独立假设和最终回退包。

## 10. 完成定义

Stage 2 启动准备只有在以下条件同时满足时才算完成：

- Stage 2 配置和路径命名空间独立；
- 静态与运行时门禁均能拒绝 Stage 1 资产；
- 750 类、长尾划分和提交格式的合成测试通过；
- 数据审计、固定划分、H1 重建和基线命令可复制；
- 不存在初赛权重、统计量或逐样本状态的隐式继承；
- 训练、验证、推理和技术报告均有可追溯哈希与环境记录。
