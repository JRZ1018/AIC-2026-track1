# 换机迁移与恢复指南

更新时间：2026-09-11（Asia/Shanghai）

## 1. 两条迁移通道

GitHub 只保存可以公开、可以审查、体积可控的内容：源码、测试、配置、规则文档、实验轻量记录、锁定依赖和迁移工具。

U 盘保存不能公开或不适合进入 Git 的本地状态：官方数据、官方 CLIP 权重、数据派生审计与固定划分、checkpoint、真实提交包，以及可选的冻结特征缓存。不要把 U 盘包提交到任何公开仓库。

## 2. 旧电脑：推送源码并制作 U 盘包

源码推送完成后，在项目根目录执行：

```powershell
git status --short --branch
git push origin main
```

先查看需要复制的文件数和空间：

```powershell
D:\aicomp\python312\python.exe scripts\transfer_workspace.py plan --include-features
```

假设 U 盘盘符为 `E:`，创建一个全新的空目录作为包目标：

```powershell
D:\aicomp\python312\python.exe scripts\transfer_workspace.py create E:\AICtrack1-private-transfer --include-features
D:\aicomp\python312\python.exe scripts\transfer_workspace.py verify E:\AICtrack1-private-transfer
```

`--include-features` 会多复制约 117 MiB 的冻结训练特征，建议保留，可避免换机后重新提取。若 U 盘空间不足可去掉该参数；这不会影响 checkpoint 或首次提交包。

默认私有包包括：

- `DataSetStage1/`：初赛官方训练集和测试集；
- `artifacts/weights/ViT-B-32.pt`：唯一允许的官方骨干权重；
- `artifacts/audits/stage1/`：类别映射、样本清单、重复簇和固定划分；
- `artifacts/experiments/20260910-p3-a1-cosine-ce/`：A1 基线 checkpoint 与诊断；
- `artifacts/experiments/20260910-p3-m1-classwise-history-3ep/`：当前 M1 首选 checkpoint；
- `submissions/20260911_m1_first/`：首份真实提交 CSV、ZIP 和 manifest；
- 可选 `artifacts/features/stage1/train_openai_vit_b32/`：冻结特征缓存。

工具会为每个文件记录相对路径、字节数和 SHA-256，并在复制后生成 `transfer_manifest.json`。它拒绝覆盖非空目标目录，也会先核验关键权重、checkpoint 和提交包的已知哈希。

## 3. 新电脑：克隆、恢复私有状态、创建环境

建议使用 Windows、Python 3.12、NVIDIA GPU。先安装 Git、Python 3.12 和与当前驱动兼容的 NVIDIA 驱动，然后执行：

```powershell
git clone https://github.com/JRZ1018/AIC-2026-track1.git D:\aicomp\AICtrack1
Set-Location D:\aicomp\AICtrack1
py -3.12 scripts\transfer_workspace.py verify E:\AICtrack1-private-transfer
py -3.12 scripts\transfer_workspace.py restore E:\AICtrack1-private-transfer
powershell -ExecutionPolicy Bypass -File scripts\setup_environment.ps1
```

环境脚本会在仓库内创建 `.venv`，从官方 PyTorch CUDA 12.8 索引安装锁定版本，并从锁定 commit 安装 OpenAI CLIP。它不会下载模型权重；模型权重只能来自已校验的 U 盘包。完成后所有命令都使用：

```powershell
.\.venv\Scripts\python.exe
```

如果 GitHub 上的 `main` 已经前进，而 U 盘 manifest 中的 `source_git_head` 较旧，保留最新 `main`，再检查这段时间是否发生了配置路径或 checkpoint 契约变化；不要盲目回退代码。

## 4. 新电脑验收

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe scripts\check_governance.py
powershell -ExecutionPolicy Bypass -File scripts\check_environment.ps1 -PythonExecutable .\.venv\Scripts\python.exe
.\.venv\Scripts\python.exe scripts\manage_upstream_references.py sync
.\.venv\Scripts\python.exe scripts\manage_upstream_references.py check
git status --short --branch
```

预期：测试与治理检查通过；CUDA 可用；官方权重和两个关键 checkpoint 哈希通过；上游参考仓库恢复到注册表锁定的 commit；`git status` 不出现数据、权重、checkpoint 或提交包。

## 5. 不要复制或上传的内容

- 不复制旧电脑的 Python 安装目录、`.venv/`、pip 缓存或 CUDA Toolkit；环境应从锁文件重建。
- 不把 `DataSetStage1/`、`artifacts/`、`submissions/`、`references/upstream/` 强制加入 Git。
- 不把 GitHub 参考仓库快照放进 U 盘包；在新电脑用锁定注册表重新同步即可。
- 不在新电脑通过 CLIP 的默认下载器重新取权重；继续使用已校验 SHA-256 的官方文件。
