### 为什么两步都做（方法学理由）

I 同时改了两个变量，若 I 提升无法判断来自时长还是下限；J 在**固定时长**下只改下限，
两者配对即可把收益归因清楚。这是"每轮只改一个主要因素"原则的具体落实，
不是无依据地堆叠实验。

## 2. seed1 门禁（写死，事后不得修改）

现行最强 seed1 为 8ep/mw0.2 候选：Top-1 `0.713759303`、macro `0.713626802`、
冲突子集 `0.310139179`。

候选进入三种子确认必须**同时**满足：

| # | 条件 | 阈值 |
| ---: | --- | --- |
| 1 | 最佳固定验证 Top-1 | **严格高于** `0.713759303` |
| 2 | macro accuracy | **不低于** `0.713626802` |
| 3 | 冲突子集 Top-1 | **不低于** `0.310139179` |
| 4 | 最佳结果不是单 epoch 异常尖峰 | 需 epoch 曲线支撑 |
| 5 | 指标全部有限 | 无 NaN / Inf |
| 6 | 哈希一致 | config、输入、初始化器、checkpoint、commit |
| 7 | 未访问 test | `scope` 声明且 `command.txt` 无 test 引用 |

### 选择规则

1. 先排除保护指标（第 2、3 条）失败者；
2. 合格者按 Top-1 从高到低排序；
3. **最多晋级两个**（本轮实际只有两个候选）；
4. 若无候选通过，判定"时长已饱和且下限已触底"，**停止加 epoch 与调权重**，
   转入 `docs/52` §10 的 layer-wise learning-rate decay；
5. 结果出来后不得修改门槛。

### 条件追加项 K（12 epochs）

仅当 **I（10ep）的 Top-1 高于 8ep 参考 `0.713759303` 且其第 9、10 epoch 仍在上升**
时，才允许预注册并运行 K（12 epochs + mw0.1），用于确认时长是否仍未饱和。
否则不测 12 epochs。
