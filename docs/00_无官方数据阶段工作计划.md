# 获奖导向工作计划（无官方数据阶段起步）

更新时间：2026-09-09（Asia/Shanghai）

## 0. 结论先行

项目不再以“实现一批常见鲁棒损失”为目标，而围绕一条可验证、可解释、适合单张 RTX 4060 8 GiB、能跨赛段复用代码但不跨赛段复用数据或模型的主线推进：

> **OpenAI CLIP ViT-B/32 + 类别感知的单模型可信度课程学习 + 参数高效微调 + 表征保持。**

核心策略：

- 初赛不计最终线上综合成绩，主要用于打通全流程、识别噪声结构、筛选方法并确保晋级。
- 复赛和半决赛分别贡献线上综合成绩的 40% 和 60%，且存在长尾，主要实验与算力预算留给这两个阶段。
- 每个新阶段从允许的 OpenAI 官方 CLIP ViT-B/32 权重重新开始，只用该阶段官方数据，不继承上一阶段 checkpoint、特征缓存、样本权重或伪标签。
- 最终只保留一个模型和一条推理流程，禁止集成、投票和测试集适配。
- “有效成绩”是最低门槛：必须高于官方基线、格式正确，训练和自动筛样全过程可复现。

获奖不能保证。提高概率的正确顺序是：先消灭无效提交风险，再建立可信验证和强基线，最后只保留有稳定增益、能解释且能复现的创新。

## 1. 已确认事实、保守假设与关键路径

### 1.1 已确认事实

- 骨干固定为 OpenAI 官方 CLIP ViT-B/32；不得改用更大骨干、OpenCLIP 或 LAION 权重。
- 当前阶段只能使用官方提供的当前阶段数据；测试集只能推理。
- 初赛为 500 类、103,218 张训练图和 24,967 张测试图；复赛为 1,500 类、297,282 张训练图和 74,896 张测试图；半决赛为 1,000 类、180,274 张训练图和 49,857 张测试图。
- 复赛和半决赛训练集有长尾；测试集类别均衡且人工精确标注。
- 线上指标为 Top-1 Accuracy；低于官方基线可能被认定为无效成绩。
- 复赛/半决赛还要提交可复现代码、说明、模型或容器环境和 PDF 技术方案。
- 截至 2026-09-09，本地尚无官方数据，原因是尚未完成报名缴费后的数据领取。
- 本机已验证 RTX 4060 Laptop 8 GiB、PyTorch CUDA 和 OpenAI CLIP ViT-B/32 权重可用。

### 1.2 保守假设

- 2026-09-20 只是团队冲刺目标，不是已由公开规则确认的正式截止时间。实际日期、每日提交次数和晋级规则以报名系统、邮件/短信和赛题群最新通知为准。
- 未明确允许前，不使用多提示平均、多裁剪 TTA、EMA 教师输出、跨阶段 checkpoint、外部物种描述或外部知识库。
- 官方类别只有数字编号时，不假设存在可用语义类名；Prompt/文本分支只在官方类名确实存在且合规后启用。

### 1.3 第一关键路径

队长应尽快完成报名与缴费、确认团队信息、进入赛题群并领取官方数据。无官方数据时可以建设工程和合成测试，但无法判断算法效果。

待向组委会确认的问题维护在 `docs/compliance_questions.md`。获得明确答复前采用最保守实现。

## 2. 原方案的主要不足

| 不足 | 为什么影响成绩 | 本版修正 |
|---|---|---|
| 工程工作包很多，但没有赢分主线 | 容易平均用力，做完模块却没有强方法 | 主线固定为可信度课程学习 + PEFT + 表征保持 |
| CE/LS/GCE/SCE 并列推进 | 它们是基线，不足以支撑创新；普通小损失筛样在细粒度任务中可能失效 | 只保留代表基线，优先验证 CLIP 语义/原型一致性和类别感知筛样 |
| 未处理验证标签本身有噪声 | 仅按 noisy validation accuracy 选模可能选错 | 分组划分、重复图隔离、多信号诊断、多种子确认、有限榜单校准 |
| 缺少阶段隔离细则 | 误用上一阶段模型或缓存有违规风险 | 每阶段从官方 CLIP 权重重启，数据与产物物理隔离 |
| 未针对 8 GiB 显存规划 | 全量端到端网格搜索会耗尽时间 | 冻结特征初筛、逐级解冻、AMP 和累积梯度 |
| 没有排行榜预算 | 容易榜单过拟合或耗尽提交次数 | 预注册提交、submission ledger、稀疏校准 |
| 未从第一天积累答辩证据 | 后期难补复现、消融和创新证明 | 自动保存配置、环境、曲线、耗时、显存和哈希 |
| 忽略项目治理问题 | `AGENTS.md` 原在 `docs/`；项目未初始化 Git | 根目录规则已迁移；P0 初始化版本控制和防泄漏规则 |
| 时间表没有门禁与止损 | 容易在弱方法上持续消耗算力 | 每阶段设置 Go/No-Go 和回退方案 |

## 3. 获奖目标和候选准入门槛

### 3.1 三层目标

1. **保底有效**：规则零违规、提交格式零错误、超过官方基线、任意结果可复现。
2. **争取省级奖并晋级**：复赛排名进入实际设奖/晋级区间；具体口径以当阶段通知确认。
3. **争取国赛奖**：在半决赛 60% 权重阶段取得稳定优势，同时准备复现包、技术报告、消融和答辩材料。

### 3.2 候选方案准入门槛

只有同时满足以下条件才进入最终复训：

- 符合数据、骨干和单模型限制。
- 相对同预算强基线，在固定划分上有稳定提升，不是只赢一次随机种子。
- 不显著伤害尾类或少样本类。
- 训练稳定且可从 checkpoint 恢复。
- 推理仍是一份 checkpoint、一次前向流程。
- 能用清晰消融解释增益来源。

默认止损：初筛单种子无增益即停止；有希望的候选再跑两个额外种子。具体提升阈值根据基线方差确定，不预先虚构固定百分点。

## 4. 总体技术路线

### 4.1 强基线层

1. **B0：冻结 CLIP 特征 + 线性分类头 + CE**。
2. **B1：冻结 CLIP 特征 + 余弦分类头 + CE**，更贴合 CLIP 归一化表征。
3. **B2：B1 + 一种代表性鲁棒目标**。优先比较 GCE 与 LogitClip-CE，只让最佳者进入后续。
4. **B3：参数高效微调强基线**。按 LayerNorm/投影层、最后一个视觉块、LoRA 的顺序，根据显存和吞吐选一个正式 PEFT 基线。

Label Smoothing 和 SCE 只作便宜对照。全参数微调只做诊断；若显存、速度或遗忘明显不利，立即停止。

### 4.2 主攻方法：Class-aware Trust Curriculum（暂定名）

围绕同一个 CLIP ViT-B/32 模型，为每个训练样本维护可复现的可信度状态：

1. **短 warm-up**：先训练分类头或极少量参数，避免噪声早期破坏预训练表征。
2. **三信号可信度**：组合类别内归一化损失、预测边际/历史稳定性、与类别原型或 CLIP 语义的相似度。
3. **类别感知归一化**：阈值在类内估计，并设置每类最低保留比例，避免全局小损失策略误删尾类和难类。
4. **软权重优先**：先连续降权，不直接删除；只有多信号长期一致时才进入严格重标注候选。
5. **课程式微调**：高可信样本先提供主监督，随后逐步吸收中可信样本；低可信样本只参与合规的一致性或弱监督项。
6. **表征保持**：约束当前图像表示与冻结的原始 CLIP 表示，限制灾难性遗忘。
7. **单模型输出**：最终只导出一个 checkpoint；推理不访问训练样本状态库。

该路线同时回应噪声挖掘、鲁棒微调、灾难性遗忘和工程复现，不复刻 DivideMix/Co-teaching 的双网络流程。

### 4.3 语义增强支线（有官方语义类名时才启用）

若官方数据明确给出物种类名，可把 OpenAI CLIP 文本编码器和固定通用模板作为语义一致性信号，并研究 DeFT、JoAPR、TrustCLIP 启发的正负提示或标签验证。必须满足：

- 只使用官方类名和固定通用模板。
- 不调用在线模型生成物种描述。
- 不引入外部百科、属性库或图片。
- Prompt 组合方式和最终推理是否合规先向组委会确认。
- 先证明它优于无语义类名也能工作的视觉原型路线。

研究证据提示：普通小损失策略在细粒度数据和 CLIP ViT-B/32 上可能明显变弱。因此“按损失删样本”只作基线，不作最终创新。

- 队长完成报名、缴费、赛题群确认和数据领取；记录正式截止、提交次数、晋级规则与联系人。

- 建立 `docs/compliance_questions.md`、`experiments/index.csv` 和 `submissions/ledger.csv`。
- 记录官方通知、邮件和群公告的日期与摘要。

验收：报名与数据权限状态明确；规则覆盖整个仓库；Git 状态可追踪。

### P0.5：上游成熟方案审计与复用排期

- 以 `docs/04_上游方案调研与复用登记.md` 为唯一人类可读动态台账，以 `docs/upstream_registry.yaml` 为机器可检查登记，完成 OpenAI CLIP、DeFT、CLIPCleaner、JoAPR、ELR、LogitClip、CoOp/Dassl 和 DivideMix 的来源、许可证、依赖、权重、数据、训练模型数量与推理路径审计。

- 将重点仓库绑定到后续工作包：OpenAI CLIP → P3；ELR/LogitClip → P2/P3 鲁棒目标；DeFT/CLIPCleaner → M2/M3 可信度与类别感知筛样；JoAPR → M5 标签修复；CoOp/Dassl → 工程接口参考；DivideMix → 仅作对照思想和排除依据。
- 每个登记候选到达其强制触发阶段时，必须得到一种可追溯结果：最小实现与实验、正式对照实验，或基于规则/许可证/资源证据的排除；P0/P1 候选优先完成。不得仅列入参考文献后遗忘。
- 真正复制或改写第三方代码时创建 `THIRD_PARTY_NOTICES.md`，记录来源文件、固定 commit、许可证和本项目修改；只借鉴论文思想时保留论文引用和独立实现说明。

验收：上游登记文档字段完整；重点候选均有触发阶段、预期交付物和退出条件；后续 P3/M1-M5 的完成定义包含上游台账回查。

### P1：数据契约和不可猜测接口

- 唯一配置入口包含阶段、训练/测试根目录、官方清单、类映射和扩展名白名单。
- 扫描器只读统计样本数、类频次、尺寸、坏图、文件哈希、精确重复和感知近重复。
- 划分时按重复簇分组，防止同图或近重复图跨训练/验证泄漏。
- 类别映射来自官方文件或明确目录语义，保存双向映射和哈希。
- 训练、验证、测试变换分离；验证和测试无随机增强。

验收：合成夹具可稳定复现审计；坏图和错误映射会显式失败。

### P2：可控噪声合成基准

生成程序化几何/纹理类别，注入可知真值的对称噪声、类别对类别噪声、样本难度相关噪声、长尾、重复和截断文件。

该基准只验证筛样 precision/recall、尾类保护、训练恢复等算法逻辑，不用于预测真实赛题收益。

验收：CE、鲁棒损失和可信度模块在已知噪声下行为符合预期，且不依赖外部真实图像。

### P3：计算经济型 CLIP 基线

- 只加载本地 OpenAI 官方 ViT-B/32 权重并记录 SHA-256。
- 支持冻结特征缓存；特征、标签、路径、数据版本、预处理配置和权重哈希绑定。
- 支持线性头、余弦头、LayerNorm/投影层、最后视觉块和 LoRA 的可配置训练。
- 支持 AMP、梯度累积、梯度裁剪、断点恢复和 OOM 诊断；不静默改变 batch size。
- 先测单卡吞吐和显存，再制定 epoch；不盲目网格搜索。

验收：CPU 小样本和 RTX 4060 AMP 单步通过；恢复后的下一步状态一致。

### P4：可信评估与选模

- 主指标为 Top-1 Accuracy；同时记录 macro accuracy、每类召回、head/mid/tail、ECE 和混淆摘要。
- 固定类分层、重复簇分组的 train/validation 清单并保存哈希。
- 明确 noisy validation 的局限，不把它当成干净测试精度的无偏估计。
- 先单种子筛选，再用 3 种子确认均值、标准差和最差种子。
- 结合 Top-1、类平衡诊断、训练稳定性和有限排行榜证据选模，不追单次榜单波动。

验收：相同配置可复现实验目录和指标；划分不随数据顺序漂移。

### P5：提交防线

- 推理不创建优化器、不更新 BatchNorm、不生成伪标签、不写回测试目录。
- `pred_results.csv` 由脚本生成，类别编号为四位字符串，文件名与官方清单一致。
- 校验表头、分隔符、编码、空格、行数、顺序、重复/缺失/额外文件和 ZIP 内容。
- 保存 checkpoint SHA-256、配置哈希、Git commit、数据摘要、推理命令、生成时间和本地指标。
- `submissions/ledger.csv` 记录提交目的、唯一变化、线上分数和结论。

验收：故意损坏的提交样例全部被拒绝；一条命令可生成并校验 ZIP。

### P6：报告与答辩证据链

- 自动保存 loss/accuracy 曲线、样本权重分布、类频次分桶、耗时和峰值显存。
- 预定义报告四张核心图：方法总览、主结果、关键消融、噪声/长尾诊断。
- 记录第三方代码/论文的许可证、commit 和改写说明。
- 初赛即做一次复现演练，复赛前完成容器或锁定环境。

验收：任何报告数字都可追溯到实验目录和命令。

## 6. 官方数据到位后的 24 小时清单

### T+0 至 2 小时：封存与规则确认

1. 确认下载来源，记录文件名、时间和 SHA-256，不传播链接或文件。
2. 原样解压到 `data/<stage>/raw/`，原始数据只读。
3. 阅读压缩包 README、样例提交和报名系统最新说明。
4. 更新正式截止、提交次数、基线、类别映射、CSV 表头和 ZIP 要求。

### T+2 至 6 小时：数据审计

1. 核对规模、类别数、坏图、截断图、重复簇和类别频次。
2. 生成数据摘要 JSON/CSV 与哈希；异常先停训并排查。
3. 创建类分层且重复簇隔离的固定验证划分；不让验证集抽空极少样本类。

### T+6 至 12 小时：建立有效提交底线

1. 缓存冻结 CLIP 训练特征并记录吞吐、时间和磁盘占用。
2. 运行 B0/B1，选择稳定的冻结特征强基线。
3. 完成测试推理、CSV/ZIP 校验和 manifest。
4. 若提交次数允许且格式已复核，提交管线校验版本。

### T+12 至 24 小时：建立 PEFT 基线

1. 运行端到端短 epoch 吞吐基准。
2. 比较 LayerNorm/投影层、最后视觉块和 LoRA 中成本最低的两个方案。
3. 选择唯一 PEFT 基线并冻结实验协议，然后才进入鲁棒学习。

24 小时验收：至少一个完整提交候选、一个冻结特征基线、一个 PEFT 基线，以及可复现的数据和实验 manifest。未达到时暂停创新方法，先修基础链路。

## 7. 实验矩阵与止损顺序

### 7.1 冻结特征初筛（单种子）

| ID | 唯一变化 | 目的 |
|---|---|---|
| A0 | 线性头 + CE | 最低基线 |
| A1 | 余弦头 + CE | 验证 CLIP 归一化表征优势 |
| A2 | A1 + GCE | 代表性鲁棒损失 |
| A3 | A1 + LogitClip-CE | 有界 logits 鲁棒对照 |
| A4 | A1 + 类别先验校正 | 长尾阶段重点验证 |

只保留 A0/A1 中较强者和 A2/A3 中较强者。

### 7.2 适配策略初筛（短程、单种子）

| ID | 唯一变化 | 目的 |
|---|---|---|
| B0 | 冻结视觉编码器 | 对照遗忘与速度 |
| B1 | LayerNorm/投影层可训 | 极低成本适配 |
| B2 | 最后一个视觉块可训 | 局部表征适配 |
| B3 | 注意力层 LoRA | 主要 PEFT 候选 |

按验证表现、吞吐、显存和稳定性选四选一，不把四条路线都带到全量实验。

### 7.3 主方法消融

| ID | 增量模块 | 必须回答的问题 |
|---|---|---|
| M0 | 最佳强基线 | 同预算参照 |
| M1 | 类内损失 + 历史稳定性软权重 | 动态可信度是否有效 |
| M2 | M1 + 原型/语义一致性 | 多信号是否减少自确认偏差 |
| M3 | M2 + 类别最低保留/课程计划 | 是否保护难类和尾类 |
| M4 | M3 + 原始 CLIP 表征锚定 | 是否抑制灾难性遗忘 |
| M5 | 严格标签修正 | 只有软权重稳定且合规后才试 |

每一步只有在前一步稳定后才继续。M5 若对阈值敏感或只有偶然榜单提升，立即回退到 M3/M4。

### 7.4 确认与最终复训

- 最佳基线与最佳主方法各跑 3 种子，报告均值、标准差和最差值。
- 最终候选从官方 CLIP 权重重新训练至少一次，不直接采用调参过程中偶然最好的 checkpoint。
- 提交前做一次断网、无测试标签环境的复现演练。

## 8. 排行榜与提交预算

每日提交上限未确认前按比例管理：

- 20%：管线和基线校准。
- 40%：通过本地门槛的关键方法。
- 20%：最终候选复核。
- 20%：截止前故障和回退储备。

每次提交前写明唯一变化、预期和失败后的处理。禁止从测试图片、提交顺序或多次榜单反馈推断标签。线上分数只作稀疏证据，不替代本地实验。

## 9. 8 GiB 单卡资源策略

- 冻结特征用于分类头、损失和阈值初筛；实际缓存大小以审计为准。
- 端到端只训练通过初筛的少数候选。
- 首次真实训练先测 samples/s、峰值显存和单 epoch 时间，再确定 epoch、batch size 和累积步数。
- 使用 AMP、梯度累积、可选梯度检查点和顺序式实验，不并行抢占显存。
- 不做大网格搜索。学习率、权重衰减、warm-up 和 LoRA rank 使用短程淘汰。
- 截止前至少留 24 小时给最终复训、推理、校验、上传失败和回退。

## 10. 分赛段策略

### 初赛：方法实验室

- 目标：超过基线、确认噪声结构、打通方法和提交、筛出一个主方法。
- 类别无长尾，先验证噪声鲁棒性和微调稳定性。
- 产出：实验协议、主方法最小版、榜单校准关系、复赛一键重启模板。

### 复赛：40% 权重，首次正式争奖

- 从官方 CLIP 权重和复赛数据重新开始。
- 重点增加类别感知阈值、先验校正和 head/mid/tail 诊断。
- 前半程完成强基线，后半程只优化已验证主线。
- 同步冻结报告大纲、复现脚本和环境。

### 半决赛：60% 权重，优先稳定和复现

- 再次从官方 CLIP 权重和半决赛数据重新开始。
- 不大规模换轨，只校准少量阶段相关超参数。
- 稳定增益、单模型合规和复现成功率优先，不押高方差 trick。
- 提前完成技术报告、模型包和演示材料。

### 总决赛：把算法优势讲成证据链

- 解释普通微调为何记忆噪声、全局小损失为何伤害难类/尾类、类感知多信号可信度与表征锚定为何有效。
- 用消融、失败案例、类频次分桶、训练曲线和复现演练支撑，不只展示最好分数。
- 所有结论对应真实运行记录，不夸大未验证效果。
