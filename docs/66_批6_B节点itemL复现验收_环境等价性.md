## 3. 发现的真实问题：`config_sha256` 依赖行尾，不能单独用作等价性判据

- A 侧 `config_sha256 = de96f7cd…`，B 侧 `= e49ed392…`，**同一份有效配置**。
- 原因：B 以 CRLF 检出且文件带 BOM，训练器对**文件字节**取哈希；A 侧是 LF。
- 佐证：A 的 `last.pt` 与 B 的 `last.pt` 在**除 `config_sha256` 与 `history`**（`history` 内嵌该哈希及吞吐计时）**之外的每个字段都逐位相同**。

**含义与处置**：`config_sha256` 是"字节哈希"，不是"有效配置哈希"。跨机器/跨平台的等价性判据
**必须**使用"配置文件内容比较 + 指标逐位比较"，不能只看 `config_sha256` 或 `git_commit`。
（该字段跨平台不稳定，未来若要用它做门禁，需先统一为 LF 并对规范化后的文本取哈希。）

## 4. `initial_validation` 为 null：已确认为续跑副作用，非失败

B 的机器在 16:53–17:33 休眠挂起并中断，随后用 `--resume` 从 epoch 6 边界的 `last.pt` 续跑。
训练器在 `epoch != 0` 时会跳过初始固定划分评估，故 `initial_validation = None`，无法在事后补出。

**但初始守卫已被隐式验证**：该守卫（`expected_initial_top1: 0.686996996` ± 0.002）在首段运行中
通过，否则训练器会在 epoch 1 前直接 `RuntimeError` 退出；且 epoch 1 的 Top-1 与 A 逐位相同
（`0.695432961`），说明初始状态完全一致。**因此无需为此重跑。**

## 5. 流程缺陷（A 方责任，已认定）

1. **任务单缺少续跑条款。** B 在暂停后重跑会遇到输出目录已存在的 `FileExistsError`，
   她按用户指示使用 `--resume`，**属对"唯一命令"的合理偏离**，A 认定其合规，
   但这是我的任务单疏漏：今后凡有中断风险的长时间任务单，必须写明续跑命令与
   `--resume` 的边界（只可从 epoch 边界恢复）。
2. **A 未在主任务单中写入 B 节点的耗时校准**，导致预计 45–60 分钟与实际 191 分钟差距过大。
   今后给 B 的预算应按 **≈15–18 min/epoch**（而非本机 5.2 min/epoch）估算，并在任务单中注明。

## 6. 本次回报的额外收获

`best.pt` 与 `last.pt` 的**逐字节不同**曾是一个疑点。经逐字段拆解，差异**只在**
`config_sha256` 与 `history`（含 `train_seconds`、`train_samples_per_second` 等计时字段），
**模型权重、优化器状态与 RNG 状态完全相同**。这条结论同时证明了：
**B 的 checkpoint 可直接用于任何需要 A 侧 checkpoint 的流程**（本地已有 A 的副本，故去重删除）。

## 7. 并行预算（据此重估）
