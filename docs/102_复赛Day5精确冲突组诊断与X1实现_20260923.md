# 复赛 Day5：精确冲突组诊断与 X1 实现（2026-09-23）

## 1. 零 GPU 诊断

诊断输入仅为 Stage2 train 审计产物 `samples.csv`、固定 `split.csv` 和
`label_conflicts.csv`，没有读取 test。

- 跨标签精确冲突组：1,877 组；对应 3,884 个样本。
- 组大小：1,756 组为 2 张、115 组为 3 张、5 组为 4 张、1 组为 7 张。
- 固定 split 后，训练侧有 1,028 个冲突样本、514 组双样本冲突，约占训练集 0.864%；验证侧有 2,856 个冲突样本，约占验证集 9.604%。
- 训练侧冲突组全部为 2 个成员；这意味着 X1 只会对训练中同一精确图片的两条矛盾标签各乘 0.5，总组权重保持为 1。

验证侧冲突比例明显高于训练侧，因此 X1 只按训练 partition 内的成员数计算权重，不能用全 manifest 的组大小惩罚只有一个训练成员的组，避免把验证重复样本错误地当成训练梯度。

## 2. X1 定义与实现

新增 `src/aictrack1/methods/conflicts.py` 的
`conflict_group_weight_lookup`：只读取当前 Stage2 审计列出的 SHA-256；返回以 manifest 行号索引的权重查找表。普通样本权重为 1，训练 partition 内同一冲突组的每个成员为 `1 / 组内成员数`。

`scripts/train_peft.py` 新增可选配置：

```yaml
conflict_loss:
  enabled: true
  mode: group_normalized
```

该开关默认关闭，因此不改变既有实验；打开时只改变训练损失贡献。若 AC 开启，X1 权重与既有 AC 样本权重相乘；不改标签、不删除样本、不改变采样、不读取 test。配置和指标会记录 `conflict_diagnostics`。

候选配置：
`configs/experiment/stage2_day5_x1_conflict_groupnorm_ac_last4_8ep_seed20260921.yaml`。
