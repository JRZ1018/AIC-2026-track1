**三条必须继承的结论**：

1. **排行榜是确定性的**（byte-identical 重跑精确得到同一分数 61.0005）→ 同配方换种子的差值
   （实测 ±0.16–0.19）是**真实种子效应**。它可用于方差诊断，但“训练多个种子、分别提交并按榜择最高”
   尚无书面合规确认，不得继续表述为已确认合法策略；**严禁种子平均/模型融合**。
2. **固定验证有分辨率下限**（`mix` 0.50 与 0.75 本地 `best_top1` 相同到 9 位小数，线上差 0.2083）
   → **"本地持平"不能作为不出包的理由**。
3. **训练损失能分辨机制（0.008–0.039）但不能分辨种子（±0.0005）**，是筛选阶段唯一可用的探针；
   但两个加权旋钮都会"按构造"降低损失，**损失低 ≠ 泛化好**，最终由线上分裁决。

  - 顺带查出两个真实缺陷：① `metrics.json` 的 `config_sha256` 是对**文件字节**取哈希，会因 CRLF/LF 与 BOM 而不同，**不能单独作为等价性判据**；② 任务单缺续跑条款，B 遇休眠中断只能自行 `--resume`。
  - B 的实测吞吐是 **721–840 s/epoch**（本机 309 s），12-epoch 端到端 191 分钟。**给 B 的预算按 15–18 min/epoch 估，不要用本机数字。**
- **item N1 已派发 B**（`docs/67`，任务单 `docs/task_orders/20260917-B-nocwh-control-n1.md`，commit `3f02eeb`）：**整块关闭 `confidence_weighting`**，其余全同，对照 `0.719480276`。这是本项目第一次测量软加权机制本身的价值。判定阈值已冻结：`|Δ₁| < 0.0015` 判为"机制中性"，**不启用全量 N2**，并停止在 `min_weight`/`history_mix`/`magnitude_mix` 上继续投入。
- **item M（16 epochs）已预注册但暂缓**（`docs/64`）：当前只有两台可用机器，M 等有节点时可直接执行，无需重新预注册。
- **反复出现的结构性现象（必须持续盯）**：两次独立机制改动都在"干净样本变好、冲突子集变差"方向上迈了同一步——lr 1.5e-6→1.75e-6（`docs/53`：Top-1 +0.001147 / 冲突 −0.002209）、K→L（Top-1 +0.001939 / 冲突 −0.003313）。**只报 Top-1 会让判定失真**，冲突子集必须并列报告；`docs/42` 证明的是人工长尾压力下的风险，复赛是否启动专项仍由真实分布审计决定。
