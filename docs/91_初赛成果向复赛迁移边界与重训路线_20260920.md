# 初赛成果向复赛迁移边界与重训路线

更新时间：2026-09-20（Asia/Shanghai）

状态：**Stage 1 → Stage 2 的唯一资产迁移判定表**。若后续官方书面答复与本文冲突，先保存
答复证据并更新规则日志、本文和运行时门禁，不允许仅凭口头转述放宽。

## 1. 先给结论

复赛可以继承的是：**代码、算法思想、工程流程、测试、报告经验、超参数起点，以及未经初赛
数据训练的 OpenAI 官方 CLIP ViT-B/32 原始权重。**

复赛绝不能继承的是：**任何从初赛 train/test 学习、统计、筛选或生成出来的模型参数与数据
状态。**其中包括初赛 H1 分类头、末四块微调权重、LoRA/Adapter、optimizer/scaler/scheduler、
EMA、特征缓存、类别原型、阈值、先验、样本权重、loss 历史、伪标签、manifest、split、类别
映射、冲突表和提交预测。

“不能继承”指不能成为 Stage 2 训练、初始化、验证、选模、推理或后处理的输入，不要求物理删除。
这些文件继续只读封存，用于审计初赛 61.8016 的来源。

初赛最优设计也不能被直接宣布为复赛方案。末四块解冻、冻结头和 AC 软加权可以作为**待证伪
的起跑假设**，但复赛类别从 500 变为 750，训练分布明确长尾；特别是 `min_weight=0.02` 可能
把本来就稀缺、困难的尾类进一步压低。复赛必须从新 H1、无软权重 CE 对照开始，再单变量验证
AC 和长尾机制。

## 2. 规则依据与项目解释

官方来源：

- 赛题 4 现行规则：`https://www.aicomp.cn/tracks/tracks-1/3714.html`
- 复赛通知：`https://www.aicomp.cn/notice/notice-1/5278.html`

官网赛题 4 现行规则明确：

1. 每个赛事阶段只能使用该阶段官方提供的数据进行训练、验证和测试；复赛不得使用初赛数据；
2. 测试集只能用于测试，不能以监督、自监督、无监督或伪标签方式参与训练；
3. 只允许 OpenAI 官方公开的 CLIP ViT-B/32 预训练权重；
4. 最终不得多模型集成、模型融合或独立模型投票；
5. 复赛训练集存在长尾，测试集类别分布均衡。

官方原文没有逐项点名“初赛 checkpoint/特征/统计量”。本项目采用以下保守且可审计的解释：

> 初赛 checkpoint、特征、原型、阈值与逐样本状态都是初赛数据的函数。将它们加载到复赛，等价
> 于让初赛数据通过派生状态参与复赛，违反“只使用当前阶段数据”的实质边界。因此在未获组委会
> 明确书面例外前，它们全部按硬禁止处理。

初赛实验结论可以由人阅读并转化为一般方法假设，因为初赛本来就承担熟悉赛题和验证方案的作用；
但 Stage 2 程序不得读取初赛实验目录来自动选择超参数、初始化参数或计算先验。

黄色资产不是普通候选，而是根据初赛证据排在前列的**高优先级复验路线**。其正确迁移方式是
“把问题写进 Stage 2 实验矩阵、优先复验并重新建立证据”，而不是复制初赛配置并改路径，也不
是默认它们在长尾复赛数据上仍然成立。

## 4. 初赛 61.8016 模型逐组件拆解

### 4.1 “初赛训练出来的头还能不能用”

- **能用**：分类头的代码、Linear/Cosine 架构选择、训练脚本、优化方法和实验经验。
- **不能用**：`final.pt`/`best.pt` 中已经训练好的权重和 bias。

这不是只因规则保守。初赛头的输出为 500 类，复赛要求 750 类，参数形状与官方类别语义本身就
不匹配；即使将来发现部分物种重叠，也不得从 500 类权重中摘取若干行拼进新头，因为这些行仍是
由初赛数据学得的派生参数。Stage 2 必须创建新的 750 类头并在复赛数据上训练。

初赛最终模型可抽象为：

```text
OpenAI 原始 CLIP ViT-B/32
  → 初赛 500 类 H1 全量线性头
  → 解冻末 4 个视觉块，冻结 H1 头
  → AC 逐样本置信度加权训练 16 epochs
  → 初赛 final.pt 与 pred_results.zip
```

迁移到复赛后的处理是：

| 组件 | 处置 |
|---|---|
| OpenAI 原始 CLIP ViT-B/32 | **保留并重新加载**，这是唯一允许复用的模型权重 |
| 初赛 500 类 H1 | **丢弃并随机重建 750 类头**；在 Stage 2 train/split 上重训 |
| 初赛末四块参数 | **丢弃**；从官方 CLIP 原始参数重新开始 last-4 训练 |
| “冻结头 + last-4”设计 | **保留为候选 S2/S3**，与 H1 和 CE 基线重新比较 |
| 初赛 AC 算法代码 | **保留为候选 S3**，逐样本历史全部清零 |
| 初赛 AC 超参数 | **仅作起点**，尤其 `min_weight=0.02` 不得未经尾类诊断直接正式使用 |
| 初赛 optimizer/epoch 状态 | **全部丢弃**，新 optimizer、新 scheduler、新 scaler、新 global step |
| 初赛最终包/线上分 | **只读审计证据**，不参与复赛任何计算 |

因此“重新训练”不是只换一个 750 类分类头：**骨干必须回到 OpenAI 官方原始权重，H1、PEFT
视觉参数和所有训练状态都在复赛数据上重新产生。**

## 5. 为什么设计也不能原样照搬

初赛 train 近似均衡；复赛 train 官方明确为长尾，而 test 均衡。这个组合会放大三类风险：

1. 自然采样使头类贡献绝大多数梯度，均衡 test 上尾类错误不会被类别频率“稀释”；
2. AC 把高损失样本降权时，可能把“尾类的真实困难样本”误当作“噪声样本”；
3. `min_weight=0.02` 允许单样本梯度缩到原来的 2%，尾类原始支持少时，有效训练质量可能进一步
   塌陷，即使总体训练 loss 更低也可能掉 Top-1。

所以复赛不能只问“AC 是否比初赛好”，而要拆成：

- 无软权重 CE 能否在 Stage 2 固定验证上建立可靠基线；
- AC 是否提高总体 Top-1，同时不损伤 macro、tail、最差类和零召回类；
- 某类表现差是原始支持少，还是被 AC 降权后有效质量过低；
- 温和采样、类感知降权预算或训练先验校正中，哪一个单变量真正改善 tail 且不伤总体。

## 6. 复赛重新训练的固定顺序

### R0：数据与合规门禁

1. 只接收 Stage 2 官方包，记录来源、字节数和 SHA-256；
2. 实测 148,695 train、37,444 test、750 类以及目录/类别 ID/提交样例；
3. 生成 Stage 2 独立 manifest、映射、split、冲突表和 B09 长尾报告；
4. 确认所有 Stage 2 配置不引用 `stage1`、`DataSetStage1` 或初赛 checkpoint。

### R1：从零重建基础表示和 H1

1. 只加载 OpenAI 官方 CLIP ViT-B/32 原始权重；
2. 在 Stage 2 train 上重新提取冻结特征；
3. 随机初始化 750 类“固定验证 H1”，只在 Stage 2 固定 train 分区上训练；
4. 冻结该 H1，记录新的基线、哈希和 provenance；它是 R2/R3 固定验证候选的共同初始化；
5. 此时不得训练或使用见过固定 validation 的全量 H1 来评估候选。

### R2：重训无软权重 CE

从官方 CLIP 原始视觉权重 + 新 Stage 2 H1 开始，训练 last-4 CE。它回答“部分解冻本身的价值”，
不能从初赛 AC checkpoint 反向关闭权重机制得到。

### R3：重训 AC 单变量

与 R2 使用相同的新 H1、split、seed、训练日程和 last-4 结构，只打开 confidence weighting。
同时报告总体 Top-1、macro、head/mid/tail、最差类、零召回类、冲突子集和每类有效训练质量。

### R4：长尾专项单变量

官网已经确认存在长尾，所以**长尾诊断是必做项**；具体机制由实测严重度决定：

- L0/接近均衡：不为“长尾”标签强加机制；保留诊断；
- L1：优先比较一个温和类均衡采样或一个仅用 Stage 2 train 估计的先验校正；
- L2/有效质量塌陷：优先实现每类最低有效质量、类感知降权上限，再与温和采样做单变量对照。

不要一次叠加采样、logit adjustment、class-aware threshold 和 AC，否则无法判断提升来源。

### R5：确认与全量复训

单种子短筛 → 少量多 seed 稳定性确认 → 锁定配方与 epoch → 在全部 Stage 2 train 上重新训练
“最终全量 H1” → 从官方 CLIP 原始视觉权重和该全量 H1 执行一次最终全量 PEFT → 锁定唯一
checkpoint → 一次标准 test 推理。

最终全量 H1 已见过原固定 validation，只能用于锁模后的全量复训，绝不能回流成为固定验证候选
的初始化器或重新参与选模。多 seed 仅做本地稳定性统计，不平均、不融合、不投票，也不依据线上
多 seed 择优。

## 7. 启动前的机器可检查清单

- [ ] 唯一模型初始化权重是官方 CLIP SHA-256 `40d365...0af`。
- [ ] `head_checkpoint` 指向本次 Stage 2 H1，而不是任何 Stage 1 H1。
- [ ] checkpoint provenance 为 `competition_stage: stage2`，类别数 750。
- [ ] manifest、split、mapping、conflict、feature cache 全部位于 Stage 2 命名空间。
- [ ] optimizer/scaler/scheduler/历史预测/样本权重从空状态创建。
- [ ] 没有程序读取 `artifacts/experiments/*stage1*`、`artifacts/features/stage1/` 或
  `artifacts/audits/stage1/`。
- [ ] CE、AC、长尾候选每轮只有一个主变量。
- [ ] tail/macro/有效质量与总体 Top-1 同时进入晋级门槛。
- [ ] test 只在锁模后推理，不参与类别先验、阈值、校准或选模。
