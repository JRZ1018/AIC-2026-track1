## 1. 模拟范围

`scripts/simulate_stage2_submission.py` 只生成合成文件名、750 个 `cls_NNN` 类别 ID 和循环预测，
不读取图片或比赛 test。默认连续构建两份 37,444 行包，并要求 CSV 与 ZIP SHA-256 分别一致。

模拟刻意使用 17 个嵌套目录和非四位数字类别 ID，以覆盖初赛格式之外的路径。提交契约设为
`relative_path` 与 `cls_\d{3}`；真实复赛必须按官方样例重新选择 basename/relative_path 和类别
模式，不能照抄模拟值。

## 2. 固定命令

```powershell
.\.venv\Scripts\python.exe scripts\simulate_stage2_submission.py `
  --output artifacts\readiness\b11-stage2-submission
```

验收项：37,444 个唯一键、顺序不变、标签全部属于显式映射、UTF-8 无 BOM、LF 换行、ZIP
根目录仅一个 `pred_results.csv`、CSV/ZIP 重打包哈希一致、manifest 记录完整。

## 3. Stage 2 台账

模板：`submissions/stage2_ledger.template.csv`。正式提交前复制为私有工作台账，并填写：

- 唯一候选、锁模时间、checkpoint/config/data/split/mapping/environment/Git 身份；
- 精确推理命令、manifest、CSV/ZIP 哈希、记录数；
- 当日提交序号与平台返回结果；
- 上一个已验签回退包及 manifest；
- 第二复核人和事实备注。

台账模板不是正式提交，不得把占位行解释为已发生记录。

## 4. 提交前 checklist

1. 官方样例已确认文件名列、类别 ID、表头、编码、压缩格式和大小限制。
2. 当前候选已锁模；checkpoint 与实验索引完全一致，测试推理后未修改映射或配置。
3. 推理只运行一次标准单模型流程，不做多 seed 融合、投票、TTA 或 test 自适应。
4. CSV 行数等于审计后的 test 数量；键集合、顺序、唯一性和标签集合全部通过。
5. ZIP 仅含规定文件；CSV、ZIP、checkpoint、config、mapping 和 manifest 哈希写入台账。
6. 第二人只复核哈希与台账，不重新生成或改写预测。
7. 提交前确认当日剩余次数；未确认前按每日最多 2 次的保守上限。
8. 平台失败时保留原包和错误截图，不覆盖；回退到上一已验签包。

test 推理发生后禁止根据预测分布、线上分数或文件内容改变标签映射、阈值、先验或训练策略。
