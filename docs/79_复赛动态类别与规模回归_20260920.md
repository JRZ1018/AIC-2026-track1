## 2. 公告规模的 manifest 级回归

测试使用以下**公告规模常量**：

- train：148,695 条；
- test：37,444 条；
- classes：750 类。

这些数值只用于开赛前容量回归，不写入 `stage2.template.yaml` 的正式数据契约。真实数据到手后仍须
只读审计；若数量不同，以官方文件和审计结果为准，不能修改数据来迎合本测试。

测试仅生成路径/manifest key，不生成 186,139 张图片：

- train key 先逆序构造，再按 UTF-8 字节序排序、检查唯一性并流式计算 SHA-256；
- test key 使用嵌套相对路径，按 `relative_path` 契约规范化，检查大小写不敏感唯一性并计算摘要；
- 相同构造的摘要被固定为回归常量，后续排序或规范化语义变化会显式失败。

## 3. 状态复杂度与资源上界

### 3.1 逐样本置信度状态

`ClasswiseHistoryWeighting` 的全部持久/查找 tensor 都是一维数组。测试同时验证：

- 2,048 条扩到 4,096 条时 tensor 字节数精确翻倍；
- 148,695 条、750 类时 tensor 总量为 7,286,055 bytes，即约 6.95 MiB；
- 任一 tensor 的元素数都不超过样本数；
- checkpoint 中没有二维逐样本矩阵，因此不存在 `N×N` 状态。

这只覆盖当前置信度加权状态，不等于承诺整次训练峰值内存；图片 batch、CLIP 激活、优化器和
DataLoader 内存仍须在正式数据冒烟时单独实测。

### 3.2 类别相关状态

分类头参数按 `C×D` 增长，不含固定 500 类形状。以真实 CLIP 图像特征维度 512 和 750 类估算：

- linear head：384,750 个参数，float32 参数约 1.47 MiB；
- cosine head：384,000 个类别权重，另有一个 scale，float32 参数约 1.46 MiB。

`classification_diagnostics` 为列出类别对混淆使用 `C²` 计数向量；750 类时为 562,500 个
int64，约 4.29 MiB。它是类别诊断状态，不是随样本数增长的 `N×N` 结构；当前规模可接受，
若后续类别数远大于公告值则需要改为稀疏混淆统计。

### 3.3 manifest key 管线

在本机 Python 3.12 的 `tracemalloc` 测量中，同时持有并处理 148,695 条 train key 与 37,444 条
test key的峰值为 30,774,062 bytes，即约 29.35 MiB；完整测量约 1.88 秒。测试门槛设为
128 MiB，给不同解释器与分配器保留余量。该数字不包含真实 manifest 的全部字段和图片元数据，
正式只读审计仍需观测进程 RSS 与磁盘占用。

## 4. 小图 DataLoader/前向冒烟

测试实际创建 4 张 8×8 RGB PNG，经 `IndexedImageDataset` 和 `DataLoader` 读取，再通过一个
不含预训练权重的 toy visual projection 与 750 类 linear head，完成前向、交叉熵和反向传播。

该冒烟只验证图片读取、batch 字段、动态输出维度与 loss 接口能连通；它不声称替代 OpenAI
CLIP ViT-B/32 的正式单 batch CUDA 冒烟。后者必须等复赛数据审计和配置冻结后另行批准。
