## 一、赛题背景

本赛题围绕以CLIP为代表的视觉基础模型在细粒度图像识别中的鲁棒微调展开。网络图像数据规模大但存在错误标注、弱相关标注、类别不均衡和难样本等问题。直接微调可能造成模型过拟合噪声标签并产生灾难性遗忘。

赛题要求在含噪标签条件下对视觉基础模型进行安全、有效、鲁棒的微调，重点关注识别精度、泛化能力和稳定性。

## 二、赛题任务

基于赛事方提供的细粒度图像训练数据，面向自然动植物类别识别任务，设计并训练高效、稳健的图像识别模型。

为保证公平性，必须严格使用 **CLIP ViT-B/32** 作为骨干网络。可研究的方向包括：

- 参数高效微调
- Prompt Tuning、Adapter、LoRA
- 噪声标签学习
- 鲁棒优化
- 样本筛选与自动清洗
- 伪标签优化
- 正则化与表征约束
- 灾难性遗忘抑制

测试集类别分布均衡，并经过人工精确标注。

## 三、数据集

### 数据来源

训练数据主要来源于互联网公开图像资源，经整理后形成含噪标签训练集；测试集由赛事方人工精确标注。

### 分阶段数据规模

| 阶段 | 类别数 | 训练样本 | 测试样本 | 特点 |
|---|---:|---:|---:|---|
| 初赛 | 500 | 103,218 | 24,967 | 含噪标签 |
| 复赛 | 750 | 148,695 | 37,444 | 含噪标签、长尾分布 |
| 半决赛 | 500 | 90,197 | 24,912 | 含噪标签、长尾分布 |

三个阶段均为自然动植物单标签细粒度图像分类。部分图片文件可能存在截断，但官方说明可通过 Python Pillow 正常读取。

## 四、算法设计要求

1. 必须使用 CLIP ViT-B/32 作为骨干网络，不得替换为其他视觉基础模型或更大模型。
2. 必须在 CLIP ViT-B/32 基础上设计鲁棒微调算法。
3. 鼓励研究参数高效微调、鲁棒损失、噪声样本过滤、伪标签、正则化、表征约束和灾难性遗忘抑制。
4. 最终提交方案不得使用多模型集成；最终结果必须来自单一模型或单一推理流程。
5. 总决赛代码必须可复现，无法复现主要结果可能被取消成绩。
6. 完整训练过程必须由最终代码直接复现；人工数据清洗不能成为最终方案的必要前置步骤，建议使用自动清洗或自动筛选。

## 五、评价指标与成绩

线上阶段主要指标为 Top-1 Accuracy：

```text
Accuracy = 预测正确的测试样本数 / 测试集样本总数
```

- 初赛：主要用于熟悉任务、验证方案和晋级，不计入最终线上综合成绩。
- 复赛：线上综合成绩占40%。
- 半决赛：线上综合成绩占60%。
- 总决赛：线上综合成绩作为客观评分的重要依据，并结合线下答辩；具体决赛细则由组委会后续公布。
- 低于赛事方公布的基线成绩，可能被判定为无效成绩。

## 六、考核重点

1. 数据挖掘与处理：识别噪声特征、样本重加权、数据清洗、难例挖掘。
2. 基础模型微调：在噪声标签下进行参数高效微调、鲁棒优化、特征约束和灾难性遗忘抑制。
3. 创新性：突破传统全参数监督微调方法。
4. 工程能力：大规模细粒度训练、算力分配、参数调优和实验复现。

## 七、约束条件

### 算法约束

- 必须使用 CLIP ViT-B/32。
- 不得使用其他视觉基础模型、商业闭源模型 API 或在线大模型推理接口替代核心识别流程。
- 不得使用多模型集成、模型融合或多个独立模型投票。

### 数据约束

- 每个阶段只能使用该阶段官方提供的数据集。
- 测试数据只能用于测试，不得参与训练，包括自监督或无监督训练。
- 复赛不得使用初赛数据；半决赛不得使用初赛和复赛数据。
- 可以使用 OpenAI 官方公开的 CLIP ViT-B/32 预训练权重。
- 赛事数据不得泄露、传播或用于比赛以外用途。
