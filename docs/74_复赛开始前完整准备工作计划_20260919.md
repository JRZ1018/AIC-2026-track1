## 1. 目标、边界与完成定义

### 1.1 总目标

在复赛数据开放前，把能离线验证的工程风险、环境风险、合规风险和执行流程尽量前移；
数据到手后先用只读事实决定策略，不把初赛的人造压力环境误当成复赛真实分布。

准备完成时应满足：

1. 初赛最佳结果、代码、配置、哈希和回退包被完整封存，复赛侧不能误引用初赛派生状态。
2. 换机、环境重建、审计、划分、训练、恢复、推理、出包和台账链路均有可执行说明和至少一次演练证据。
3. 类别数、类别 ID 格式、测试目录层级和样本数均不再依赖初赛硬编码。
4. 复赛数据到手后可在 4 小时内完成只读审计、格式判定、长尾分布判定和首轮配置冻结。
5. 长尾问题有预注册的诊断指标与启动条件；只有真实数据触发条件后，才投入专项算法开发。
6. 正式训练仍从 OpenAI 官方 CLIP ViT-B/32 和复赛数据重新开始，不携带初赛 checkpoint、
   逐样本状态、类别先验、置信度历史或调度器状态。
7. 所有正式结果能追溯到数据、划分、配置、环境、代码、checkpoint 和提交包哈希。

### 1.2 本计划不做的事

- 不继续刷初赛榜，不产生新的初赛提交。
- 未单独批准前不启动 GPU 正式训练、不读取复赛 test 做模型选择、不生成线上提交。
- 不提前猜测复赛类别 ID、目录结构、压缩包哈希或真实长尾程度。
- 不把初赛最优超参数称为复赛最优；它们只是低成本起跑点。
- 不使用外部数据、模型融合、种子平均或多模型推理。
- 不为了凑满预计时长而扩大工作；每批以验收项完成为结束条件。

## 2. 必须先校正的事实口径

### 2.1 初赛真实分布与压力测试不是一回事

`docs/10_初赛数据审计报告.md` 的实测口径是：

| 口径 | 每类样本数 | 中位数 | 是否长尾 |
|---|---:|---:|---|
| 初赛全量训练集，103,218 张 | 201–213 | 207 | 近似均衡 |
| 固定 train 子集，82,592 张 | 161–170 | 166 | 近似均衡 |
| 人为构造的 L1 长尾压力训练集 | tail 多为 8、mid 多为 33、head 约 168–170 | 不适用 | 人为长尾 |

`docs/42_复赛迁移长尾压力与分层诊断验收.md` 中“8 张桶类均召回 21.29%、31 个
零召回类”来自第三行的人为压力测试。它证明的是：**当前方法遇到严重类频偏斜时会饿死
尾类**；它不证明初赛原始数据存在长尾，也不能单独证明复赛一定需要某个具体长尾算法。

因此，复赛长尾工作的正确顺序是：

1. 现在准备审计、指标、测试夹具和决策门槛；
2. 数据到手后实测分布；
3. 根据真实分布和训练期有效权重诊断，决定仅监控、温和处理还是启动专项机制；
4. 不在数据到手前投入两天实现未经触发的复杂长尾方案。

赛事材料目前描述复赛训练数据存在长尾，因此必须做好快速启动准备；但代码投入仍以实际审计为准。

## 3. 优先级规则

所有事项按以下原则排序：

1. **P0：会让第一天直接跑不起来或违规的风险**——环境恢复、类别映射、出包契约、阶段隔离。
2. **P1：会让结果不可复现或无法判断的风险**——台账环境哈希、动态类别测试、全流程空跑、恢复测试。
3. **P2：只有真实数据触发后才有收益的算法工作**——长尾最低保留、类感知阈值、采样和先验校正。
4. 所有正式训练按“基线 → 单变量 → 多种子确认 → 全量固定轮次 → 锁模推理”的顺序执行。
5. 每批都必须能独立审阅和回滚；不同批次不顺手夹带未经批准的训练或重构。

### B09：长尾诊断与“是否启动专项”的预注册

**目的**：提前准备判断能力，而不是提前押注算法。

  recall、零召回类；同时报告 head/mid/tail 和冲突/非冲突子集。
- 预注册三个决策级别：
  - **L0 近似均衡**：只保留诊断，自然采样，不开发专项机制；
  - **L1 温和长尾**：先测试温和采样或单一先验校正；
  - **L2 严重长尾/有效质量塌陷**：启动每类最低有效质量、类感知降权上限和温和采样对照。
- 在看到复赛标签分布前冻结判定阈值；建议初始触发指标以相对比率为主，避免把“50 张”之类
  与数据规模绑定的绝对数误用到新数据。
- 保留 `docs/42` 的 L1/L2 压力测试作为工程回归，不把它当复赛分布证据。

**暂不做**：正式接入复杂类感知阈值、两阶段重采样、大范围 alpha 网格或多种机制叠加。

**产物**：预注册文档、指标 schema、合成边界测试和一条命令生成分布报告。

**验收**：同一输入重复运行结果一致；均衡合成数据判为 L0，预设温和/严重夹具分别触发 L1/L2；
报告能区分“原始样本少”和“被软权重压低后的有效样本少”。

**资源/预计**：CPU，60–90 分钟。

### B10：复赛起跑配置与实验矩阵预注册

**目的**：数据到手后按有限矩阵启动，不临场无边界搜索。

**起跑假设**：

- OpenAI CLIP ViT-B/32 官方原始权重；复赛 H1 随机初始化并在复赛数据上训练。
- 首个 PEFT 候选以初赛 AC 为参考：末 4 个视觉块、冻结头、batch 64、weight decay 0.01、
  gradient clip 1.0、视觉学习率 `1.75e-6`、16 epochs。
- 软权重参考：warmup 1、momentum 0.8、history_mix 0.5、`magnitude_mix=0.75`、
  `min_weight=0.02`。
- 上述数值全部标记为“Stage 1 起点、Stage 2 必须复验”，尤其 `min_weight=0.02` 可能在
  真长尾数据上过度抑制困难/稀缺类。

**预注册顺序**：

1. H1 冻结视觉线性头；
2. CE + 末 4 块部分解冻，不开软权重；
3. AC 软权重单变量；
4. 仅在 B09 触发 L1/L2 后加入一个长尾变量；
5. 单种子短筛通过后才申请多种子；多种子通过后才全量固定 epoch。

**产物**：全部 `execution_enabled: false` 的模板、单变量表、晋级/停止门槛和资源估算表。

**验收**：没有虚构数据哈希；每项只有一个主变量；所有正式配置在审计结果写入前不能运行。

**资源/预计**：CPU，45–75 分钟。

## 5. 复赛数据到手后的头 4 小时 runbook

此阶段不以“尽快开训”为目标，而以一次性把输入事实定准为目标。任何数量或格式异常都先停。

### 0:00–0:30：原始来源与只读落盘

1. 记录官方来源、下载开始/完成时间、文件名、字节数和 SHA-256。
2. 原始压缩包设为只读；解压到独立 `DataSetStage2`，不覆盖 Stage 1。
3. 复核平台公告、复赛提交次数、截止时间、材料要求和跨阶段权重规则。
4. 若官方基准或通知变化，先更新事实文档，不沿用旧模板继续。

### 0:30–2:00：数据契约与结构审计

1. 确认 train/test 数量是否为当前公告的 148,695/37,444，类别是否为 750。
2. 检查图片可解码性、扩展名、通道、尺寸、目录层级、同名文件和坏图。
3. 确认官方类别 ID 来源、格式、目录名与官方 ID 的关系；建立显式映射并验签。
4. 只对训练集做类别支持、重复簇、跨标签冲突和近重复审计。
5. test 仅做推理必需的结构/完整性审计，不做基于内容或预测的训练决策。

### 2:00–3:00：长尾分布判定

1. 生成 B09 预注册的支持数统计和可视化数据。
2. 判断 L0/L1/L2；记录触发了哪些预注册指标。
3. 检查固定验证切分对尾类是否可行；重复簇不可跨侧。
4. 若近似均衡，长尾专项降级为监控项；若温和/严重长尾，才解锁相应工作包。

### 3:00–4:00：正式配置冻结与冒烟

1. 把实测路径、数量、映射、manifest 和哈希写入正式 Stage 2 配置。
2. 运行静态/运行时隔离门禁和 1 batch CPU/CUDA 冒烟。
3. 生成固定 split；复跑验证确定性和重复簇零跨侧。
4. 形成审计报告并提交人工审阅；审阅通过前不启动正式 H1。

**头 4 小时完成门禁**：官方来源可追溯、数量/结构明确、映射无歧义、分布级别已判定、
split 可复现、Stage 2 配置没有 Stage 1 引用、冒烟通过。

## 6. 数据审计通过后的首日顺序

### S1：重建绝对基线

1. 从官方 CLIP 原始权重提取复赛训练特征。
2. 在复赛固定 train 上随机初始化并训练 H1；不加载初赛头。
3. 建立冻结视觉 CE 基线和 raw-image 口径核验。
4. 只有官方提供有语义的类别名称且规则允许时，才增加零样本文本基线；数字 ID 不强行做零样本。

### S2：建立部分解冻基线

1. 末 4 块、冻结 H1、CE、自然采样作为第一条可比线。
2. 学习率 `1.75e-6`、16 epochs 仅作为起点；先短程曲线检查，不直接承诺全量 16 epochs。
3. 同时报告 Top-1、macro、冲突子集、类别分层和资源，不只看总 Top-1。

### S3：复验噪声软权重

1. 关闭软权重对照先成立。
2. 再加入初赛 AC 参数；检查低频/高频类的平均权重、有效质量和降权率。
3. 若 `min_weight=0.02` 导致某类有效质量塌陷，立即停止，不用总分上涨掩盖。

### S4：条件式启动长尾工作

- **L0**：不增加专项算法，只保留诊断。
- **L1**：一次只比较自然采样与温和采样，或一次只比较无/有先验校正。
- **L2**：先实现最低有效类质量/类感知降权预算，再与自然采样做单变量对照；通过后才讨论采样。

禁止一开始把最低保留、类感知阈值、采样、logit adjustment 同时叠加，否则无法归因。

## 7. 条件式长尾专项工作包

以下 LT 批次不在当前默认队列，只有 B09 与真实审计触发后才可批准。

### LT1：最低有效类质量与类感知降权预算

- 目标不是强行让每类权重分布相同，而是防止整类被全局高损失规则压空。
- 对每类记录原始样本数、`sum(weight)`、低于阈值比例和最小有效质量。
- 类保护只约束下界/降权预算；不提升可疑样本到高置信，也不人工改标。
- 验收需同时看总体 Top-1、tail/macro、零召回类、冲突子集和 head 损失。

### LT2：确定性的温和采样

- 比较自然采样与一个预注册的温和指数；默认不先上完全类别均衡，以免放大尾类噪声。
- sampler 状态必须进入 checkpoint，恢复后样本序列可复现。
- 只有 LT1 或无软权重对照稳定后才执行，避免采样与降权交互无法归因。

### LT3：最小类别先验校正

- 只使用复赛 train 侧估计先验；validation/test 分布不反推训练参数。
- 只测试一种简单校正及其强度零点对照，不开大网格。
- 若复赛 test 官方说明均衡，仍需以本地固定验证和多种子稳定性决定是否保留。

### LT4：压力回归与真实数据验收

- 先保证 `docs/42` 的人造压力夹具不退化，再以复赛固定验证做正式证据。
- 人造压力指标只作失效模式回归，不能替代复赛真实效果。
- 若总体提升来自牺牲大量 head 类或冲突子集，结论必须标为权衡，不得宣称全面改进。

## 8. 合规、测试与资源总门禁

### 8.1 合规

- 单模型、单次推理；不得融合多个 seed、checkpoint、增强分支或模型输出。
- 未获书面确认前，不把初赛训练权重用于复赛初始化。
- 不使用外部数据；官方 CLIP 权重身份固定并验签。
- test 不参与训练、阈值、类别先验、选模或误差分析。
- “多 seed 取最高是否允许”“每日提交次数”“类别 ID/文件列格式”均以复赛书面规则为准。

### 8.2 测试层级

1. 单元测试：映射、路径、阶段、数量、哈希、sampler、恢复、出包。
2. 合成集成测试：3/7/500/750 类与 37,444 行模拟包。
3. 迁移空跑：改名数据根目录的全链路。
4. 干净机冒烟：环境与私有状态恢复。
5. 正式数据冒烟：只在审计后跑 1 batch，再申请训练。

### 8.3 资源审批

每次 GPU 或全量磁盘扫描前必须单独报告：命令、数据范围、预计时长、显存、CPU、磁盘新增、
可恢复点、停止条件和是否读取 test。未经批准只允许轻量代码、文档和合成测试。

## 10. 每批统一汇报格式

每个获批批次结束时只按以下口径汇报，避免“做了很多”但无法验收：

1. 本批实际完成项与未完成项；
2. 修改文件与关键差异；
3. 测试命令、通过数和已知警告；
4. 发现的新事实/风险，以及是否改变后续优先级；
5. 实际耗时与资源；
6. Git 状态、是否 commit、是否 push（默认不 push）；
7. 建议下一批，但不自动开始。
