## 4. 三个需要 A 知悉的发现

### 4.1 `best.pt` 内部**没有**记录 `base_loss`

A 的清单称本次改动含 "metrics/checkpoint provenance"。实测：
- `metrics.json` ✅ 记录了 `"base_loss": {"kind": "gce", "q": 0.7}`；
- **`best.pt` 顶层 18 个键中不含 `base_loss`**，独立打开 checkpoint 无法直接看出它是 GCE 训练的。

不过 checkpoint 内嵌了 `config_sha256 = b93f24655fe06276d5fb2916fcffcf4a904f89448a11f40b407339cf81c300bd`，而该配置文件明确声明 `base_loss.kind=gce`，因此**provenance 可间接恢复**。
checkpoint 已内嵌的其余身份：`competition_stage`、`training_scope`、`visual_input_resolution`、`position_interpolation`、`mode`、`num_classes`、`normalize_features`、`best_top1`、`selection_rule`、`config_sha256`、`split_sha256`、`train_manifest_sha256`、`class_mapping_sha256`、`clip_weight_sha256`、`head_initializer_sha256`、`data_loader`、`runtime`、`trainable_state`(96 张量)。**建议后续把 `base_loss` 也写进 checkpoint**（B 未改代码，仅报告）。

### 4.2 `py -3` 在本机不可用于 CUDA（已在任务单授权范围内处理）

A 的命令示例用 `py -3`；本机 `py -3` → `Python313\python.exe`（3.13.0）+ **torch 2.12.0+cpu（CPU-only）**。
任务单写"优先使用项目 Python 环境"，故使用 `D:\aicomp\python312\python.exe`（3.12.10 + torch 2.11.0+cu128）。
队列脚本内部经 `sys.executable` 拉起训练器，**无硬编码解释器**，故无脚本级冲突。

### 4.3 A 的 `train_peft.py` 还夹带了 320 支持，但本机 `clip_resolution.py` 只允许 336

同步进来的 `train_peft.py` 把分辨率分支改成 `visual_input_resolution in (320, 336)` 并传 `target_resolution=visual_input_resolution`；
而本机 `src/aictrack1/models/clip_resolution.py` L42-43 仍是 `if target_resolution != 336: raise ValueError("only the preregistered 336-pixel diagnostic is supported")`。
→ 本批 336 不受影响（已跑通）；**但若将来让 B 跑 320 配置，会在此处立即报错**，需 A 同时同步该文件。
