- 经用户提供公网 IP `101.132.160.118`，使用既有私钥以 `root` SSH 登录成功；`nvidia-smi` 检出 NVIDIA L20、49140 MiB、驱动 570.195.03。`/opt/aic-venv/bin/python` 中 PyTorch 2.11.0+cu128、CUDA 12.8，`torch.cuda.is_available()` 为 `True`。
- 系统盘 `/dev/nvme0n1` 40 GiB 挂载 `/`；数据盘 `/dev/nvme1n1` 75 GiB 挂载 `/data`。**数据盘设备容量 75 GiB，但 ext4 文件系统只有约 49 GiB，已用 43 GiB、余 6.4 GiB**；后续正式训练前应在保留快照的前提下核对并扩展文件系统，不应误以为有 32 GiB 可用空间。
- `/data/AICtrack1/DataSetStage2` 文件数核对：train 148,695、test 37,444，train 750 个类别目录。远端 `artifacts/weights/ViT-B-32.pt` 的 SHA-256 为 `40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af`；远端 C2 全量最终 `final.pt` 为 `bda8a11b27fb3706ad172757963ef84c4a0e14778e7b2bf51653cd1bfdf45848`，两者均与本机逐文件哈希一致。
- 初次轻量 cuDNN 探测报错：PyTorch 编译依赖 cuDNN 9.19.0，运行时找到 9.2.0。**GPU 可见不等于训练可用**；故先修复并复测，而没有直接启动正式训练或释放旧实例。

## 推荐迁移顺序与门禁

1. 用户对快照服务及持续计费作具体确认后，基于**已停机的旧实例**制作含系统盘+数据盘的自定义镜像；等待镜像状态“可用”，核对两盘容量和快照。阿里云官方说明该操作会为每块云盘创建快照。
2. 复制自定义镜像至华东2（上海），等待目标地域镜像“可用”；跨地域原云盘不可直接挂载。快照与镜像会持续计费，应记录 ID 和计费起点。
3. 检查上海 GPU 库存、最终实例规格、镜像、两盘大小、网络、安全组、登录密钥、抢占时长/价格上限、**节省停机中断模式**和最终价格。下单须另行取得具体确认；不以临时 ¥3.21/小时报价批准未知配置。
4. 新实例运行后核验两盘挂载、CUDA/PyTorch、代码/数据/权重哈希，跑不访问 test 标签的轻量冒烟；新公网 IP 由控制台实测，不沿用北京旧 IP。新实例 16 vCPU 为旧机一半，正式训练前对 DataLoader worker 数进行受控吞吐测试。
5. 新机验证、关键资产回传并获得旧机释放确认后，才释放北京旧实例；检查未随实例释放的 75 GiB 数据盘、快照、镜像和可能的 EIP 是否继续计费。清理这些计费资源须逐项验明和批准。
