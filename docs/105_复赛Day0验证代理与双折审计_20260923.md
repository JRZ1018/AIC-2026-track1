## 2. 主要发现：旧固定折存在显著的组大小组成偏差

| 指标 | 旧固定折（largest-first） | 新诊断折（seeded-random） | Stage 2 train 全体 |
|---|---:|---:|---:|
| 验证数 | 29,737 | 29,737 | 148,695 |
| 跨标签精确冲突样本在验证中的占比 | 2,856 / 29,737 = **9.60%** | 769 / 29,737 = **2.59%** | 3,884 / 148,695 = **2.61%** |
| 非单例近重复组样本在验证中的占比 | 14,980 / 29,737 = **50.37%** | 3,115 / 29,737 = **10.48%** | 16,264 / 148,695 = **10.94%** |
| 重复簇跨 train/validation 泄漏 | 0 | 0 | 不适用 |
| 类别覆盖；train/validation 最少支持数 | 750/750；4/1 | 750/750；4/1 | 750 类 |

旧算法按重复簇大小**降序**放入验证，导致几乎所有非单例组样本进入验证；这不是数据泄漏，但使验证集在重复/冲突样本上的组成远离完整训练集。新算法只改变组遍历顺序为 `SHA256(seed, group_id)`，保持每类目标数、最低训练支持、重复簇隔离和旧默认行为不变。它的冲突与非单例组占比更接近 Stage 2 train 全体；这**不能证明**它等同官方隐藏测试分布，只是更合理的独立诊断代理。

最初尝试“仅换随机种子、沿用 largest-first”时，两折验证重合 16,511 张（55.5%），跨标签冲突仍为 2,856 张；因此该候选折**弃用**。采用 seeded-random 后验证重合 5,969 张（20.07%），与各自 20% 的自然重合规模接近。旧 C2 固定折模型训练时见过新折验证的 **23,768 / 29,737** 张，因此**绝对不能拿旧 C2 checkpoint 直接评估新折**。新折上的任何 PEFT 对照必须从 OpenAI 官方权重和新折 train 重新训练 Stage 2 H1 与视觉部分。

## 3. 指标台账复核与读数边界

`scripts/audit_stage2_metrics_index.py` 逐个解析 25 个 Stage 2 运行的原始 `metrics.json`，核对最佳 epoch 的 Top-1/macro/tail 与 `experiments/index.csv`，结果 **25 个运行、0 个不一致字段**。这验证了索引抄录，但不验证旧固定折的代表性。

尤其要区分：`tail_accuracy` 是尾类**按样本加权**准确率；`evaluated_class_mean_accuracy` 才是尾类**按类平均**召回。例如固定折 R3 最佳 epoch 14 对应 67.6565% vs 66.1618%，C2 seed 20260921 最佳 epoch 7 对应 67.4920% vs 66.1039%。尾类最少只有 1 张验证样本，个别类召回与零召回数波动大，不能依赖单类值做门槛。

这次发现给“验证约 68% 而线上约 57%”提供了一个**可能的测量偏差来源**，但不能将约 11 分差直接归因于划分算法：隐藏测试分布未知，历史固定验证与线上包也不是完全相同的模型/训练范围。不得据此反推测试标签或用榜单逐项调参。

## 4. 对 `docs/104` 实验门禁的修订

1. 原固定折仅用于与已完成的 R2–C2 结果**配对比较**；新机制不能只因旧折提升就认定会在线上提升。
2. 新诊断折作为评估代理的第二支柱；先在同一旧固定折 checkpoint 上做 D0–D4 头部诊断，再对晋级机制**重训新折 H1/PEFT**。不能跨折复用视觉权重或已见过验证样本的头。
3. 两折结果分别报告，不直接平均为“官方成绩”；分别给出整体、macro、tail 样本加权、tail 类均、冲突/非冲突和零召回。新折仍是 noisy-label train 的子集，不是隐藏 test。
4. 若旧折与新折方向相反，暂停全量训练，先做训练内组别/冲突敏感性与预处理核验；不通过更大超参搜索掩盖评估不稳定。
